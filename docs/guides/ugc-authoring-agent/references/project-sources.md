# Project sources

JSON/YAML content can contain one record or an array. Preserve unknown fields, comments and stable content IDs when making focused changes. Names, paths, namespace, projectId and useId are separate identities. A file rename does not rename a content ID.

Species learn skills; skills and marks reference effects defined in `createEffects`. Traits and emblems use mark references. Cross-package references use the dependency's projectId and require declared npm dependencies; resource namespace references have a separate shape. Consult actual nearby examples and types instead of inventing either format.

Keep rules media-free. Define stable resources in `data/resources` with `id`, `kind`, `source`; associate content through `data/presentations` with `target.kind/id`. Usage slots reference resource IDs. `assets` is the default media directory; other ordinary package directories are supported. Species may use icon, portrait and battle; battle renderer is explicitly `image` or `seer2-swf`. Skills use sfx, marks use icon. HTTP(S) references are not downloaded by authoring tools. Source media replacement changes the next build, not an existing battle. When media moves, update its resource source without changing its ID. Cross-package references use `{namespace, id}` and require an installed dependency.

Language files live in `locales/<language>/<namespace>.json|yaml`. Reuse the project's i18next namespaces and FormatJS variable contract. Plain template text in the workspace is not a rendered battle description; dynamic values require real battle context. Missing references and partial drafts may remain on disk, but checking, building and testing must report their errors.

Follow the host's fixed description color convention (canonical source: `docs/guides/content-presentation.md`, section 固定配色约定, when the host repository is available). Ordinary mark names are cyan (`markName`); adverse and exceptional marks form ONE orange display subtype (`status`), not all marks or all negative effects. A `<mark>namespace:id</mark>` reference uses the target's existing `status` / `exceptional` tags to select that subtype. Do not modify gameplay tags to obtain a color. `markName` and `status` wrap literal text, not IDs; use `mark` for an actual object reference. The guaranteed-hit property uses `guaranteedHit`, distinct from the rule variable `sureHit` and from receiving a guaranteed-hit mark. Never replace semantic categories with arbitrary hex colors or generic emphasis during a format repair.

Resolve references from actual project/dependency records, preserving namespace and stable ID. A localized name or filename is not an identity. Do not infer a reference or gameplay effect from descriptive text. Query available context and content before suggesting a target, and report unresolved or ambiguous references without silently rebinding them. A future shared reference/variable schema and cross-tool diagnostics are design requirements recorded in that document under 描述引用的后续规范方向, not capabilities that the current SDK/MCP already guarantees. Passing the current formatting tests alone does not prove reference integrity.

For sustained effects, use the existing template test as a starting point: miss/hit, repeated application, parameter change, source transfer/removal, natural expiry, supported waiting-point restore and deterministic full battles. Tests should run the actual npm artifact in an independent installation. Keep media/package-content assertions: they catch source-only files omitted by the npm files list.
