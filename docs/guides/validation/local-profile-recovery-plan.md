2026-11-13 更新：补充更换 UID 的断开、保存、重连顺序及失败分支；新增用例的执行状态见独立记录。

## 1. 责任与环境

#212 补齐功能并交付自动化回归，#263 执行本表并保存证据。缺实现记录为 blocked 并回流 #212；已实现但行为错误记录 fail。不得把 blocked、skip 或未测计入通过。

首版目标矩阵如下。执行前核对实际发行平台；若发行平台增减，显式更新矩阵和原因。

| 宿主     | 目标环境                                                     | 隔离方法                                           |
| -------- | ------------------------------------------------------------ | -------------------------------------------------- |
| Web      | Windows Chrome、macOS Safari、Linux Firefox 的执行时稳定版本 | 独立浏览器用户目录/站点数据；记录精确版本和 origin |
| Electron | Windows、macOS、Linux 实际发布的安装产物                     | 新 OS 用户或隔离 userData，记录安装包摘要、架构    |
| CLI      | Windows、macOS、Linux 项目支持的 Node 版本                   | 新 `--profile-dir`，使用构建后的发行 CLI           |

Web 离线定义为 UI 已加载后切断所有外网和后端访问，验证资料操作无网络依赖；本单不额外承诺首次离线下载或冷启动网页壳。重启用本地提供同一 origin 的静态物料且阻断后端/外网，分别记录页面壳可访问与资料离线能力。Electron 和 CLI 则断网后冷启动已安装物料。

## 2. 公共夹具

准备资料 A：固定 UID、中文昵称、两支不同名称及规则集的队伍、不同精灵 ID 和技能顺序、仓库精灵、非默认当前队伍、非默认音量/渲染/日志过滤设置。资料 B 使用不同 UID 和不同队伍；A2 使用 A 的 UID 但修改昵称、队伍和设置。

另准备：缺失 species/skill/ability/emblem/ruleSetId 的合法资料、截断 JSON、错误字段类型、越界队伍索引、重复精灵 ID、未知字段、未知版本、超限文件和带伪造 token/admin 字段的文件。使用生成的测试数据，不将真实个人备份或凭据提交仓库。

比较 data 的规范化摘要以及逐字段结构，不能只比较数量；检查 UID、昵称、精灵 ID/顺序、全部属性、规则集、当前队伍和所有支持设置。`exportedAt`、appVersion 和目标本地 revision 不要求相等。每次测试保留源备份摘要，确认源文件未被改写。

## 3. 跨宿主互换矩阵

每个格子均先从源导出 A，在干净目标导入，重启目标，再导出并比较；然后在目标编辑一项、再次导出回原宿主的干净位置，检查 CLI 和不同渲染器未使用的字段也未丢失。

| 来源 / 目标 | Web  | Electron | CLI  |
| ----------- | ---- | -------- | ---- |
| Web         | 待测 | 待测     | 待测 |
| Electron    | 待测 | 待测     | 待测 |
| CLI         | 待测 | 待测     | 待测 |

九个方向至少各一次，其中三条同宿主对角线使用另一台设备；其余方向可复用两台设备。上述每个目标平台至少执行一次离线持久化、一次恢复和一次失败保留检查；不能用 macOS 上三个进程替代 Windows/Linux 安装版证据。浏览器跨 origin 也要通过显式文件迁移验证，不依赖共享站点数据。

## 4. 可复现用例

| 编号 | 操作步骤                                                                           | 必须观察的结果                                                                                                          |
| ---- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| P01  | 清空隔离位置；断网创建昵称；记录 UID；关闭进程重开两次；改昵称                     | UID 不变；没有认证请求；仅持久提交成功后显示已保存                                                                      |
| P02  | 拒绝读取存储；启动；重试；选择临时资料                                             | 不把读取失败认作空目录，不覆盖原资料；临时状态明确                                                                      |
| P03  | 首次写入拒绝/磁盘只读；创建；恢复可写后重试                                        | 同一内存 UID 被保存，不能产生第二个 UID                                                                                 |
| P04  | 已有 A；填满配额/磁盘；修改队伍并保存                                              | 旧持久 A 未变，内存编辑可导出；恢复空间后可重试                                                                         |
| P05  | 已有 A；损坏当前记录；重启                                                         | 原始损坏数据保留，不自动写默认资料；可以导出原始数据或恢复                                                              |
| R01  | 按九格矩阵导出、干净恢复、重启、再导出                                             | 全字段继承；CLI 不消费的设置不丢；源文件不变                                                                            |
| R02  | 目标为 B，预览 A 后取消；再确认替换                                                | 取消零变化；提交后完整 A，恢复点完整 B                                                                                  |
| R03  | 目标为 A，导入 A2；恢复上一份                                                      | 同 UID 仍需确认；恢复后完整 A，revision 递增                                                                            |
| R04  | 连续两次导入同一 data，不同导出时间再导入                                          | 返回 unchanged；不重复精灵/队伍，不改 revision 和恢复点                                                                 |
| R05  | 导入所有损坏/未知版本/未知字段/超限夹具                                            | 整份拒绝，定位错误，当前和恢复点摘要均不变                                                                              |
| R06  | 导入缺失内容资料；重启；重新导出；选择队伍；切换到包含引用的环境                   | 数据无损；缺失项可见；无法开局时明确指出引用；环境补齐后可使用                                                          |
| R07  | 在导入事务提交前、提交后分别终止进程并重启                                         | 只能看到完整旧版或完整新版；恢复点与版本一致                                                                            |
| R08  | 同 origin 两窗口/同目录两个 CLI 进程；同时预览；先后提交                           | 一个成功，另一冲突/忙；旧计划不能覆盖新编辑                                                                             |
| R09  | 设置 debounce 尚未结束即导出；写入失败再导出                                       | 成功导出当前一致快照，或明确失败；不能静默导出旧设置                                                                    |
| M01  | 构造相同/冲突的 player-data 与 player、损坏仓库、缺失设置                          | 合法数据迁入；冲突需选择；损坏不覆盖；旧键不被自动保存改写                                                              |
| M02  | 迁移中注入写失败/进程终止，再次启动                                                | 无半份新资料；可重新迁移；原始旧键完整                                                                                  |
| E01  | 安装版创建 A；关闭应用；升级到被测物料后断网重开                                   | 使用同一 userData，UID 和资料保持；安装版本和路径有记录                                                                 |
| E02  | 主窗口 A 打开远程服，关窗重开；窗口修改后请求保存                                  | 初始 UID 一致；临时编辑明确；只有主窗口确认才能写入                                                                     |
| E03  | 远程编辑期间主窗口修改资料，再请求保存；测试取消和关窗                             | 报冲突并重新预览，取消不改主资料，关窗不假称已保存                                                                      |
| E04  | 非法 frame/远程 origin/未登记窗口调用资料请求                                      | 全部拒绝；无法读取路径、管理凭据或任意本地文件                                                                          |
| C01  | CLI init/show/set-name/export/inspect/import/recover/repair/unlock；进程退出再运行 | 命令语义、退出码、JSON 输出一致；show 不产生 UID                                                                        |
| C02  | CLI 通过 --use-profile 选队本地对战；再运行 simulate/replay                        | 采用昵称/队伍但席位独立；批处理不创建或改变资料                                                                         |
| I01  | 同 UID 连 A/B 两服；令两服公布相同 serverId，使用不同 endpoint                     | 不共享 token/account 登录状态；每服独立颁发席位                                                                         |
| I02  | 用复制 UID、sessionId 或 seatId 请求他人房间动作                                   | 服务器拒绝；必须有有效 token 和房间成员权限                                                                             |
| I03  | 当前登录本服账号，切换环境；新设备仅导入资料后连接                                 | 环境切换 accountId 不变；新设备未自动登录，需认证                                                                       |
| I04  | 在导出前种入测试账号 token、管理 cookie、OAuth 状态；检查备份                      | 所有敏感字段和值均不存在；伪造这些字段的备份导入被拒                                                                    |
| I05  | 有房间/匹配/对局时尝试恢复，再退出活动重试                                         | 首次阻止；不同 UID 按断开、保存、重连顺序生效，管理权限不变                                                             |
| I06  | 已连接时预览不同 UID 的 B，先取消，再确认；记录连接事件和保存事件                  | 取消不写入也不断开；确认后关闭旧连接才保存 B；重连会话 profile.id 为 B，旧席位不沿用                                    |
| I07  | 分别注入断开失败、资料保存失败、保存成功后重连失败                                 | 断开失败不保存；保存失败保留 A，重连使用 A；重连失败保留已保存 B，重试使用 B                                            |
| I08  | 已登录账号甲时更换 UID，分别测试有效和失效凭据；再以游客重复                       | 有效凭据经服务器验证后仍为账号甲且会话使用新 UID；失效凭据进入登录流程；游客获得新会话；不能恢复旧 profile 冒充切换成功 |
| I09  | 已连接时恢复同 UID 的 A2；离线时导入不同 UID 的 B                                  | A2 不因 UID 规则强制断开或退出账号；离线导入 B 不自动联网                                                               |
| I10  | 多窗口共享资料时更换 UID；远程窗口仍持旧快照时主窗口更换 UID                       | 共享使用者先协调断开，无法协调则阻止提交；远程快照不被热更新，采用新 UID 必须断开重连                                   |
| S01  | 服务器 A 做原服备份恢复；按原账号提供商重新登录                                    | serverId 和账户空间保留；本地资料、队伍不依赖该恢复                                                                     |
| S02  | 将 A 备份克隆为新服；导入个人资料和环境材料                                        | 新 serverId；默认无旧玩家/管理授权；UID/环境不授予认证                                                                  |

I01/I02 可复用已有回归，但须在被测提交运行并记录结果；不能只贴历史测试文件。S01/S02 复用服务器备份能力和独立目录/数据库，不在本单新造服务器恢复实现。原服恢复与克隆同时覆盖 SQLite/PostgreSQL；没有 `TEST_DATABASE_URL` 时 PostgreSQL 只能记为 skip/blocked，不能记 pass。

文件 adapter 的 R07 至少在三个发行 OS 上做真实进程终止；Web 用事务失败注入加浏览器强制关闭验证。不以进程终止代替硬件掉电保证，也不要求本单承诺不支持的文件系统语义。

## 5. 执行顺序与证据格式

先完成 schema/adapter/迁移自动化，随后跑三宿主基本能力，再执行九格互换，最后做安装版、双服及恢复/克隆。执行中发现缺实现立即记录对应 #212 缺口，其余独立场景可继续。

每次运行建立独立记录目录和清单，至少包含：

```yaml
case: R01-web-to-cli
status: not-run # pass | fail | blocked | skip | not-run
commit: <完整 SHA>
artifact: <发行版本和安装包/CLI 摘要>
platform: <OS、版本、架构>
runtime: <浏览器/Electron/Node 精确版本>
source: <匿名化设备/宿主/origin>
target: <匿名化设备/宿主/origin或隔离目录>
fixture: <夹具名称和 SHA-256>
steps: <脚本路径或逐步操作记录>
expected: <断言>
actual: <实际观察>
evidence: [<日志、截图、结构比较结果的路径>]
defect: <失败或阻塞所对应 issue>
```

记录须附时间、网络阻断方式、清理步骤以及是否重新启动真实进程。截图只显示必要 UID 后缀/测试账号；日志不包含真实凭据。自动化命令以实现后的 `--help` 和 package scripts 为准，设计文档中的新 CLI 命令不能在实现前作为执行成功证据。

## 6. 关闭条件

所有验收条目都能对应上表用例及实际证据；九格互换完成；每个目标平台完成基本持久化、恢复、失败保留；双服隔离、管理隔离、原服恢复/克隆边界都有记录。未解决 fail/blocked、仅有 CI 配置或仅有单元测试时不关闭。平台范围变化须明确记录用户接受的范围调整。

#263 只引用 #212 的功能提交，不把 #212 关闭当作验收通过。本方案表格定义验收标准，不用其中的步骤描述代替执行证据。
