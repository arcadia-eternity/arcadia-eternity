# 内容包管理

`/content` 统一内容包项目与环境管理。内容包页管理 UGC 源项目；环境页管理 npm 依赖和环境配置。首次使用会创建具名默认环境，普通本机使用无需启动服务器。完整接口见[统一环境与服务器管理](unified-management.md)。

## 内容包项目

本机内容包页列出可编辑项目，提供新建、打开、导出源码和从列表移除；从列表移除仅取消登记，不删除源文件。编辑、校验、构建和试战复用作者工作区。源项目修改不会自动改变正式环境。

成功打包后使用“用于环境”，宿主校验任务产物后转到环境页选择目标。版本进入该环境的编辑草稿，点击“保存并应用”后生效。相同归档可以重复用于多个环境；同名同版本但材料不同不能覆盖原安装。

## 环境依赖与配置

- 每个环境独立保存 npm 声明和锁文件，管理直接依赖、来源和规则。不同环境可使用不同包版本；同一环境内同名内容包只有一个版本。
- 编辑环境时可手工填写版本范围、选择已有材料，或通过系统文件选择器加入 `.tgz`。已有未保存配置不会因加入材料而丢失。远程环境通过相同的依赖声明和宿主登记来源应用，不取得本机文件权限。
- “移出环境”删除依赖声明，不保留已移出列表。其他包仍需要它时，须明确连同依赖方一起移出。所需的间接依赖由 npm 解析。
- “保存并应用”准备、安装和校验新组合，成功后更新环境；失败保留原可用环境。准备禁止 npm 生命周期脚本和作者模块执行。
- “本地使用”持久保存所选环境；新对局捕获该环境内容与配置，已有对局继续持有原内容。
- “内容来源”提供下载策略、来源登记和本机材料维护。材料不是可编辑源项目；卸载不会删除源 tgz、队伍、仓库或环境已经捕获的独立材料。基础包由程序管理。

旧 `disabled` 字段读取时忽略，在工作区下一次改写前将原 manifest 归档到 `migration-backups`，新文档不再保存它。旧包库全局选择仅用于一次性迁移到具名环境，随后删除迁移状态；公开包库快照没有启用字段。

## 高级工具与网页边界

“设置 → 高级工具”提供折叠的联机托管与诊断，包括明确启动托管、停止和状态读取。桌面离线对战与 UGC 试战使用本地对战流程，加入别人的对战只连接对方服务器；这些操作均不应启动本机联机服务。复用战斗内核与内容加载逻辑不要求另开执行进程。“高级服务器项目管理”兼容原有 npm 项目登记、重命名、按锁文件安装、准入、校验、启动、移出列表、导出和导出验证。普通包管理无需手动登记服务器目录。

本机写操作使用受主 frame 校验保护的 Electron IPC、固定 CLI 子进程和受宿主标识保护的父子进程 IPC。持久托管默认回环监听，可信管理页可显式保存网络设置并重启；地址展示不证明真实 LAN/公网可达。桌面可通过系统文件选择器导入来源注册表，并与独立服复用 ManagedProjects 的获取/锁定管线；托管进程借用同一个客户端工作区，不重复安装服务器包库。

授权管理员通过 `/content` 管理目标服务器的环境与绑定，通过 `/management` 管理账户、授权和备份；两者使用认证 HTTP，复用本地管理页面。普通玩家没有这些写权限；远程管理窗口仍不能调用本机文件系统 IPC。管理目标、游玩连接和本机内容选择分别保存。

普通网页端 `/content` 按位置展示服务器公开环境或当前房间的包和固定版本，不提供本机安装、卸载或环境写入。未进房间时仍可查看配对服务器的公开目录。私人 Challenge 另有明确的文件/HTTPS 导入：双方在客户端准备固定环境，由玩家沙箱宿主执行，不把个人环境写入服务器公共目录。网页端隐藏本机创作入口，直接访问创作／本机服务路由显示本地工具说明；网页队伍编辑和正常对战继续可用。

服务器未公开依赖图时，界面明确说明无法展示，不把未知依赖显示成“无依赖”。读取失败时也不声称队伍兼容。

## 队伍与缺失内容

持久化草稿与当前内容解析分开处理。队伍及仓库保留原始 ID、属性、特性、纹章和技能列表，缺少定义不会删除或替换。编辑器仍可保存、导出草稿，开战须通过目标对局检查。

- 未加载精灵显示占位和原始 ID，无法计算的能力值显示 `—`。
- 未加载技能逐项显示原始 ID，并继续占用容量。编辑已加载技能保留其他类别与未解析技能；容量不足时提示，不静默覆盖。用户可以明确移除缺失技能。
- 浏览草稿不修正已保存性别；未知种族导入不补造身高、体重等值。显式切换种族仍属于现有的重新配置操作。
- 选择器和编辑器逐项报告精灵、技能、特性、纹章的缺失 ID。恢复同 ID 的定义后重新解析；不根据显示名猜测迁移。
- 包详情展示引用此包的队伍，选择变化后直接展示相应队伍的引用情况。这里检查内容引用，不代替服务端完整合法性校验。

## 验证

- 前端组件与缺失引用：`pnpm --filter @arcadia-eternity/web-ui test:run`
- 前端类型：`pnpm --filter @arcadia-eternity/web-ui type-check`
- 桌面管理与 IPC 边界：`node --test packages/web-ui/electron/test/*.test.mjs`
- 真实产物与服务：`ARCADIA_DESKTOP_REAL_HOST=1 node --test packages/web-ui/electron/test/content-library-real.test.mjs packages/web-ui/electron/test/local-battle-real.test.mjs`
- 真实桌面窗口：先构建 CLI 并启动前端开发服务，再执行 `ARCADIA_DESKTOP_GUI_TEST=1 node --test packages/web-ui/electron/test/content-library-electron.test.mjs`；默认使用 `http://127.0.0.1:4173`，可用 `ARCADIA_DESKTOP_GUI_URL` 指定。测试隔离应用数据，仅替代原生文件选择器的返回值，其余使用真实 preload、IPC、npm 和服务进程。
- 浏览器交互与移动端：`PLAYWRIGHT_CHROME_CHANNEL=chrome pnpm --filter @arcadia-eternity/web-ui exec playwright test e2e/content-manager.spec.ts e2e/team-builder.spec.ts`

普通桌面本地对战和个人队伍编辑使用所选具名环境最近成功准备的内容组合，沙箱执行与名称、说明、资源展示来自同一组合。新目标准备中或失败时继续使用原可用组合；新局捕获组合并持有租约，之后切换内容不会改变当前对局。作者调试使用独立预览窗口，见 [本地试战生命周期](./local-trial-lifecycle.md)。

作者构建成功后通过“用于环境”选择消费此产物的环境。宿主按成功 pack 任务核对路径与产物哈希，不接受前端指定任意归档路径。

内容编辑草稿通过已注册的 Pinia 持久化插件与 localDataStorage 按项目保存，存储失败沿用全局提示。刷新或重启后恢复修改和原始基版本，并与当前文件重新核对冲突。保存只清除已成功保存文件的草稿，放弃清空当前项目；只读安装包不恢复或写入编辑草稿。

真实包库测试使用 `examples/ugc/slow` 的实际 npm tgz，覆盖安装、环境准备、校验、启动、公开内容读取，以及卸载资源库中的包后服务器独立材料仍可用；高级项目测试另覆盖导出、重装及本地代码编辑。它们不代替签名安装包的跨平台验收。

普通桌面组合的静态捕获、资源租约、并发准备与真实 Worker UGC 效果回归可单独运行：`pnpm --filter @arcadia-eternity/web-ui test:desktop-local-content`。库与宿主回收边界使用 `node --test packages/web-ui/electron/test/content-library.test.mjs packages/web-ui/electron/test/local-battle-host.test.mjs packages/web-ui/electron/test/local-content-owner.test.mjs`。真实宿主回归需先构建 server 与 CLI，再运行 `ARCADIA_DESKTOP_REAL_HOST=1 node --test packages/web-ui/electron/test/content-library-real.test.mjs`。
