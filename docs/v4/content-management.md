# 内容包管理

`/content` 采用任务导航、包列表、单包详情三栏；窄屏改为列表与详情逐层进入。默认管理本机已安装内容，房间内容独立只读显示。界面不要求玩家创建或命名“环境”。

## 本机内容包

只有 Electron 本地端提供安装、启停、版本切换与卸载。包库位于应用数据目录的 `content-packages`，以 `library.json` 记录元数据，安装树与内容组合放在宿主私有目录。前端只传目标包句柄和明确的 npm 版本，不传命令或路径；本地文件使用系统选择器。

- 添加本地 `.tgz` 或 `@scope/name@1.2.3` 等明确 npm 版本。来源对话框说明包及其依赖会在本机运行；选择文件或点击“安装并启用”后，客户端完成检查、安装和启用，不再弹出第二次确认。npm 生命周期脚本始终禁用。
- 已安装与已启用分开。可以并存同包多个版本，同一组合只能启用一个。安装其他版本会直接切换目标版本；没有公共工坊或自动发现最新版。
- **开关直接表示目标状态**，没有“应用”按钮。宿主持久化目标，再在后台解析依赖、校验内容、准备运行实例。连续修改以最后一次选择为准，过期候选不会覆盖较新的选择，页面离开后仍继续执行。
- 页面区分目标选择与当前可用内容，显示“准备中／已就绪／未能启用”。失败保留最近可用版本和未完成目标；可以直接调整选择或重试，不需要重新确认。下次打开客户端会恢复目标；较新目标仍有问题时先恢复最近可用内容。
- 依赖解析由 npm 处理；安装操作允许该包声明的依赖闭包在本机运行。已启用包的依赖详情展示当前组合的实际解析结果。高级服务器项目的本地代码编辑继续沿用 `local-development` 策略。
- 安装、启停内容包和重开客户端只准备本机内容，不启动联机服务。只有明确选择“由本机托管联机对战”才启动服务；若已主动托管，内容变化通过私有 IPC 更新新房间的默认内容，已有房间继续持有原实例。停止托管后，后续包选择不会重新启动服务。
- 停用并等待准备完成后才能卸载。只删除受管安装，不删除源 tgz、队伍或仓库。过期候选目录自动删除；成功使用过的组合目录暂保留，运行实例则在旧房间全部释放后回收。
- “需处理”列出安装目录／包文件丢失；组合失败同时在状态区显示实际原因。异常安装可以停用后移除记录，再重新安装。

普通运行库保留在详情的依赖清单，不伪装成独立精灵内容包。官方基础内容始终保留，也支持不启用任何自定义包的本机服务。

## 高级工具与网页边界

“设置 → 高级工具”提供折叠的联机托管与诊断，包括明确启动托管、停止和状态读取。桌面离线对战与 UGC 试战使用本地对战流程，加入别人的对战只连接对方服务器；这些操作均不应启动本机联机服务。复用战斗内核与内容加载逻辑不要求另开执行进程。“高级服务器项目管理”兼容原有 npm 项目登记、重命名、按锁文件安装、准入、校验、启动、移出列表、导出和导出验证。普通包管理无需手动登记服务器目录。

本轮写操作只使用受主 frame 校验保护的 Electron IPC、固定 CLI 子进程和受宿主标识保护的父子进程 IPC，服务保持回环监听。没有新增开放目录、上传发布服务或远程管理写接口。

网页端 `/content` 只展示当前房间实际提供的包和固定版本，复用已有公开内容读取接口。不会合并服务器全部组合、下载代码、安装、启停或升级。未进房间时显示官方基础内容和空状态。网页端隐藏创作入口，直接访问创作／本机服务路由显示本地工具说明；网页队伍编辑和正常对战继续可用。

服务器未公开依赖图时，界面明确说明无法展示，不把未知依赖显示成“无依赖”。读取失败时也不声称队伍兼容。

## 队伍与缺失内容

持久化草稿与当前内容解析分开处理。队伍及仓库保留原始 ID、属性、特性、纹章和技能列表，缺少定义不会删除或替换。编辑器仍可保存、导出草稿，开战须通过目标对局检查。

- 未加载精灵显示占位和原始 ID，无法计算的能力值显示 `—`。
- 未加载技能逐项显示原始 ID，并继续占用容量。编辑已加载技能保留其他类别与未解析技能；容量不足时提示，不静默覆盖。用户可以明确移除缺失技能。
- 浏览草稿不修正已保存性别；未知种族导入不补造身高、体重等值。显式切换种族仍属于现有的重新配置操作。
- 选择器和编辑器逐项报告精灵、技能、特性、纹章的缺失 ID。恢复同 ID 的定义后重新解析；不根据显示名猜测迁移。
- 包详情展示引用此包的队伍，选择变化后直接展示相应队伍的引用情况。这里检查内容引用，不代替服务端完整合法性校验。

## 验证

- 前端组件与缺失引用：`pnpm --filter @arcadia-eternity/web-ui test:run`
- 前端类型：`pnpm --filter @arcadia-eternity/web-ui type-check`
- 桌面管理与 IPC 边界：`node --test packages/web-ui/electron/test/*.test.mjs`
- 真实产物与服务：`ARCADIA_DESKTOP_REAL_HOST=1 node --test packages/web-ui/electron/test/content-library-real.test.mjs packages/web-ui/electron/test/local-battle-real.test.mjs`
- 真实桌面窗口：先构建 CLI 并启动前端开发服务，再执行 `ARCADIA_DESKTOP_GUI_TEST=1 node --test packages/web-ui/electron/test/content-library-electron.test.mjs`；默认使用 `http://127.0.0.1:4173`，可用 `ARCADIA_DESKTOP_GUI_URL` 指定。测试隔离应用数据，仅替代原生文件选择器的返回值，其余使用真实 preload、IPC、npm 和服务进程。
- 浏览器交互与移动端：`PLAYWRIGHT_CHROME_CHANNEL=chrome pnpm --filter @arcadia-eternity/web-ui exec playwright test e2e/content-manager.spec.ts e2e/team-builder.spec.ts`

创作页的草稿试战已接入 `/local-battle` 配置和完整战斗界面，直接复用现有本地内核；不创建新的进程或联机服务。会话统一管理草稿快照、临时队伍、展示覆盖和战斗清理，见 [本地试战生命周期](./local-trial-lifecycle.md)。已安装 npm 代码包与普通离线对战的接入仍是独立工作。

真实包库测试使用 `examples/ugc/slow` 的实际 npm tgz，完成检查、准入、组合、校验、启动、公开内容读取、同一进程内自动切换、旧房间保留原内容、新房间使用新选择及卸载；高级项目测试另覆盖导出、重装及本地代码编辑。它们不代替签名安装包的跨平台验收。
