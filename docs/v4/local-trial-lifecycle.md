# 本地试战的数据生命周期

创作试战进入现有 `/local-battle` 配置页，再进入 `/battle?dev=true`。战斗使用现有 `NativePackLoader` 和 `LocalBattleSystemV4`，与普通本地对战共用构造流程，不增加进程、监听端口、联机房间或 npm 代码执行入口。

## 所有权

| 数据                                       | 所有者                                   | 创建和释放                                                                                         |
| ------------------------------------------ | ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 作者草稿                                   | 现有作品库                               | 离开创作页开始试战前保存；试战结束不删除或回写草稿                                                 |
| 已准备的发布快照、基础内容、依赖及临时队伍 | `LocalBattleSession`                     | 建立一次性导航票据时深复制并冻结；取消时释放，成功进入战斗后由内核持有已捕获内容，释放原始启动快照 |
| 已保存队伍                                 | 原有 `petStorage`                        | 配置页将临时队伍与已有队伍组合展示；启动时复制选中的队伍，不写入队伍存档                           |
| 精灵、技能、印记名称和展示数据             | 会话持有的展示租约                       | 从同一次内容加载结果建立；退出或启动失败时同步恢复之前的内容与文本，再异步清理内核                 |
| 本地战斗及其订阅、计时器、运行时快照接口   | 会话交给 battle store 的 `IBattleSystem` | 使用完整战斗页；`cleanup` 终结该会话，并保证内核只清理一次                                         |

创作页在校验后继续编辑不会修改已准备快照。开始试战前保存的是当前编辑，参与战斗的是已准备快照。重新校验才能更新下一次试战。

创作基础数据使用带原生锁文件的基础包原始清单，作品和依赖在准备时一并捕获。桌面端通过已有素材读取通道加载基础包；不把旧工作区拼接清单作为可固定版本的作品基础，也不关闭锁文件校验。

## 状态与转移

`configuring → starting → routing → active → disposed`

- `configuring`：只持有快照与临时队伍；关闭配置页即释放。
- `starting`：同一会话拒绝重复启动；取消会立即标记失效，即使内容创建稍后完成，也只清理结果，不绑定 battle store 或跳转。
- `routing`：配置页卸载属于向战斗页移交。跳转成功后战斗页接管；跳转失败释放已创建的战斗和展示数据。配置页仍在时允许使用相同快照重试，否则销毁会话。
- `active`：battle store 持有受管接口，页面离开、结束后退出和显式清理均调用同一清理路径。结算仍在战斗页时保留内容供展示。
- `disposed`：终态，不能再次启动。原有队伍、作品库和服务器连接地址不属于该会话，不随它释放。

普通本地对战也使用同一会话管理，其展示数据不需要覆盖。

## 导航与失效

票据只在当前应用内存中存在，一次领取后删除；最多保留四个未领取票据，三十分钟后实际释放。跳转失败立即取消票据。刷新页面、重启客户端或重用旧链接时显示“试战快照已失效”，禁用开战；不会静默使用另一份队伍或基础内容。

路由或启动异步返回时检查会话所有权。清理 battle store 前比较受管接口身份，旧会话不能清掉后来绑定的战斗。离开战斗的守卫等待原对局清理；战斗页延迟卸载也只清理自己持有的接口。

展示租约保留精确的前一份记录和文本，不用对象深合并恢复。重叠会话乱序释放时跳过已释放的父租约，避免恢复已销毁试战的数据。新的房间内容、数据重载或重置取得展示所有权后，旧租约只释放自身引用。

## 验证重点

通过会话接口验证不可变快照、配置放弃、创建中取消、重复启动、失败重试、路由失败、旧异步响应、重复清理和清理异常。展示测试验证恢复原房间、清除临时键、乱序释放和后续加载的所有权。界面回归从创作、草稿保存、试战配置到真实技能/印记结算，再退出并检查临时数据清除与队伍未改写。

原生桌面回归：启动前端后执行 `ARCADIA_DESKTOP_GUI_TEST=1 node --test packages/web-ui/electron/test/creator-trial-electron.test.mjs`。使用隔离的应用目录和真实作品存储、preload、IPC，检查技能实际结算、退出恢复，以及战斗前、中、后联机托管均保持 `idle`。
