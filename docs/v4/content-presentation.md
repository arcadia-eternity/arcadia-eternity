# 内容表现与资源引用（v2）

一个内容包可以同时携带规则、表现、素材和多语言。源数据分开维护，工作台按对象 ID 组合展示。战斗规则产物 `dist/content.json` 不包含表现配置或素材位置。

## 作者源文件

- `data/species/`、`data/skills/`、`data/marks/`：规则定义。
- `data/presentations/`：表现定义。`id` 是稳定的表现记录标识；`target.kind` 为 `species | skills | marks`，`target.id` 是本包对象 ID。同一对象最多一个表现定义。
- `data/resources/`：资源定义。`id` 是包内稳定标识，`kind` 为 `image | audio | swf`，`source` 为包根目录相对路径或 HTTP(S) URL，可选 `name` 为作者界面名称。可选 `tags` 中的 `background`、`music` 用于全局背景／音乐列表。
- `locales/<language>/<namespace>.yaml`：名称与 ICU 描述，通过内容 ID 关联。

以上分类内支持子目录、JSON/YAML、单记录和记录数组；不要求每个对象拆成三个文件。素材可以放在包内任意普通目录，`assets/` 是默认导入位置。禁止路径穿越、符号链接及依赖、构建、内部工作目录。

```yaml
# data/presentations/puni.yaml
id: puni-display
target: { kind: species, id: pet_puni }
icon: puni-icon
portrait: puni-portrait
battle:
  renderer: image
  source: puni-portrait
```

```yaml
# data/resources/puni.yaml
- id: puni-icon
  kind: image
  source: assets/puni/icon.png
- id: puni-portrait
  kind: image
  source: assets/puni/portrait.png
```

表现用途包含 `icon`、`portrait`、`cry`、`sfx`、`background`、`music`，以及 `battle.renderer/source/fallback`。`renderer` 显式为 `image` 或 `seer2-swf`；回退必须是图片。用途引用资源 ID，不直接填写文件路径或 URL。跨包引用用 `{ namespace: other-pack, id: shared-icon }`，由安装后的 npm 依赖图验证可访问性。

## 描述格式与检查

内容描述统一使用 ICU：变量写 `{power}`、`{stack}` 等扁平名称，支持 `plural` / `select`；不使用 `{{mark.stack}}`、点路径、HTML 属性或 `[93E312]文字[-]` 色码。允许的语义标签为 `markName`、`status`、`guaranteedHit`、`damage`、`heal`、`shield`、`buff`、`debuff`、`rage`、`strong`、`emphasis`，印记引用写 `<mark>namespace:id</mark>`。名称字段仍是普通文本。

描述中的普通印记名称用 `<markName>血红印记</markName>`（青色）；**不良／异常是印记中的同一个展示子类**，用 `<status>烧伤</status>`（橙色），不是所有印记都属于它。天气、护盾印记等名称仍使用普通印记样式；不能仅凭效果有负面影响就将其归为异常。`<mark>` 引用会读取目标现有的 `status` / `exceptional` 标签，共用这个子类的配色；其他标签及未分类目标使用普通印记样式。展示分类不修改战斗规则标签。

`markName` / `status` 是纯文字高亮，不猜测对象 ID；需要导航、图标和悬浮详情时使用 `<mark>` 引用。技能性质“必中”使用 `<guaranteedHit>必中</guaranteedHit>`；“获得必中印记”使用印记样式。恢复数值、怒气等继续使用各自语义标签。工作台、图鉴和战斗共用样式，并提供浅色／深色配色。

### 固定配色约定

**状态：已确定，2026-11-01。** 本节是内容描述的配色约定；工作台、图鉴、战斗以及面向外部 AI 的作者指引均遵循它。颜色表达展示类别，不充当对象身份或战斗规则。

| 展示类别           | 标签或引用                                                    | 浅色主题          | 深色主题          | 分类边界                                                             |
| ------------------ | ------------------------------------------------------------- | ----------------- | ----------------- | -------------------------------------------------------------------- |
| 普通印记名称       | `markName`；普通目标的 `mark` 引用                            | 青色 `cyan-700`   | 青色 `cyan-300`   | 包含未归入不良／异常子类的印记，如弱点记号、血红印记、天气和护盾印记 |
| 不良／异常印记名称 | `status`；带 `status` 或 `exceptional` 标签目标的 `mark` 引用 | 橙色 `orange-700` | 橙色 `orange-300` | 不良与异常合并成一个展示子类；不是所有印记，也不是所有负面效果       |
| 技能性质“必中”     | `guaranteedHit`                                               | 黄绿色 `lime-700` | 黄绿色 `lime-300` | “获得必中印记”仍使用印记名称样式；规则字段 `sureHit` 不是这个标签    |

现有数值与文字修饰继续使用下表，不用于反推印记类别：

| 用途                   | 标签                  | 当前色板／样式（两种主题共用）       |
| ---------------------- | --------------------- | ------------------------------------ |
| 伤害数值               | `damage`              | `orange-400`                         |
| 恢复数值               | `heal`                | `green-400`                          |
| 护盾数值或泛指护盾机制 | `shield`              | `cyan-400`                           |
| 增益表述               | `buff`                | `emerald-400`                        |
| 减益表述               | `debuff`              | `purple-400`；不等于“不良／异常印记” |
| 怒气数值               | `rage`                | `yellow-400`                         |
| 强调／语气             | `strong` / `emphasis` | 加粗／斜体，不替代对象类别           |

这些名称对应共享渲染器 `packages/web-ui/src/i18n/richDescription.ts` 的主题色板。内容作者写语义标签，不写十六进制颜色、HTML 属性或组件样式。页面不能自行覆盖普通／异常印记配色。主题可为可读性调整明度，但改变类别含义或色系必须显式修订本约定、作者指引和回归检查，不能在格式修复中顺带更改。

不要为了颜色添加或删除规则的 `tags`：这些标签可能参与战斗行为。元数据不完整时保留原记录，另行修正展示或数据问题。纯文字高亮不等于可解析的对象引用；同名、同色均不代表同一对象。

战斗界面用实例的真实 `{stack}`；工作台、图鉴等只有定义时保留 `{stack}` 占位，不把初始值当作当前战斗层数。非法语法或未支持的标签会显示诊断，包含当前未选中的 `plural` / `select` 分支。

运行 `pnpm --filter @arcadia-eternity/web-ui test:content-locales` 检查基础包及内置模板所有语言的描述，并验证工作台、游戏的实际渲染路径。浏览器 CI 自动执行此检查，失败信息包含源文件和对象 ID；基础包、模板或渲染代码变动都会触发。

基础包语言记录必须对应清单声明的精灵、技能或印记，CI 同时检查仅有名称的记录，避免删除对象后留下失效翻译。未绑定的独立资源不因此删除。所有描述来源共用 ICU 渲染，包含服务器记录上的默认文本；不再根据来源切换 Markdown／HTML 解析器。

### 描述引用的后续规范方向

**状态：待设计，未作为新协议实现。** 当前 `<mark>namespace:id</mark>` 引用、工作台的印记选择、跳转与悬浮详情继续可用。下一步要明确引用的统一表示、联想来源和检查规则；此处记录约束，不提前规定新的序列化语法。

1. **身份与显示分开。** 引用表达对象类型、所属命名空间和稳定 ID；存储不依赖翻译名、文件路径、颜色或列表位置。显示名随语言切换，文件移动不改变引用。跨包引用按实际依赖和可见内容解析，不能凭同名猜测目标。
2. **联想选择对象。** 人可以按名称、别名或 ID 搜索，候选显示类型、所属包和当前语言名称；确认后保存稳定引用。没有明确目标的纯文字仍是文字，不自动补成引用。精灵、技能、印记和资源能否共用一种写法，以及各自可用的展示用途，留待设计。
3. **统一解析与检查。** 编辑器、构建／CI、SDK 和 MCP 应共用同一套引用解析与诊断规则，避免各自维护正则。检查对象是否存在、类型是否正确、依赖是否可见，以及所有 ICU 分支中的引用。诊断应指出语言、描述所属对象、源文件和文本位置，并区分引用缺失与翻译回退；不静默删除或绑定到同名对象。
4. **变量也有明确契约。** 定义可公开变量的名称、类型和可用上下文，区分定义预览与战斗实例；联想只提供当前可用变量，检查未知变量、标签重名和 `plural` / `select` 类型要求。没有实例时不能编造动态值。
5. **人和 AI 使用相同事实。** 人看到候选名称、图标、解释与修复入口；AI 从 MCP／SDK 获得稳定 ID、类型、命名空间、可见依赖、变量契约及结构化诊断。当前焦点只是上下文，不是写入授权。说明文字中的引用只建立展示关系，不创建技能或印记的战斗行为。
6. **迁移可核对。** 正式方案应能识别现有 `<mark>` 引用并保留目标、名称回退、跳转和层数预览。草稿与外部文件版本保护继续生效；存在歧义时报告问题，不批量猜测迁移。

目前 CI 已覆盖 ICU 语法、受控标签、残留色码、分类样式和组件渲染。上述通用引用完整性检查、跨工具共享诊断和变量联想契约尚未完成，不能把当前“格式检查通过”当作“所有描述引用均有效”。

## 构建与加载

构建生成 `dist/presentation.json`，其 `version` 为 2，包含 `bindings`、`resources`、`locales`、`defaultLocale`。本地资源记录保留稳定 ID，并生成 source/SHA-256/bytes/MIME；远程资源只声明 URL，不下载、代理或缓存。未被引用的已声明素材也保留。

包清单的 `arcadia.presentation` 指向该产物；npm 的 `files` 必须包含产物和全部已声明的本地素材。基础包通过 `pack.json.presentation` 引用同格式的产物，由基础包构建生成。

加载器检查对象目标、重复关联、依赖可访问性和文件完整性。浏览器获取服务器批准的表现目录，在 UI 边界解析资源 ID；实际图片、声音、SWF 由使用它的组件按需加载。固定环境保持自己的资源版本。

## 工作台与外部修改

对象页面的“形象与声音”修改独立表现草稿；资源导入复制文件并创建独立资源定义草稿。选择资源写入 ID。资源页面可查看反向引用并修改素材位置。

移动规则或资源定义文件时，ID 不变即可重新扫描定位。仅移动素材文件时会产生缺失诊断，作者在资源定义更新 `source` 后，原有对象关联继续有效。缺失引用保留，不猜测重绑。资源名、路径和内容哈希都不是身份。

表现、资源、规则和语言共用文件版本检查、改动核对、部分保存结果和 YAML 锚点保护。外部修改不会自动覆盖未保存输入。基础包在工作台只读。

## 格式迁移

旧 `assets.json.mappings`、`assetRef/iconRef/sfxRef` 和规则记录内的 `presentation` 不再作为作者源格式。基础包、内置模板与独立模板仓库已改为分离定义。显示目录中的派生 `presentation` 仍供游戏组件使用，它不回写规则源文件。

旧包必须迁移并重新构建；不能仅将旧产物版本号改为 2。模板首次安装的上游提交需要与此协议一起发布；本地开发可用新生成的 SDK 物料执行 `setup --sdk-dir`。
