# Arcadia content authoring

Work in the author's content project. Ask for the desired game behavior when its trigger, target or lifetime is ambiguous. Use the SDK and host version actually available to the project; `arcadia.sdkApi` is an API compatibility version, not an engine build identity.

1. Read `package.json` and the actual source layout: `data/species`, `data/skills`, `data/marks`, `src`, `assets`, `locales`, `test` and `arcadia.config.mjs`. Some older projects still use a root `content.json`; follow their manifest rather than assuming it. Do not edit generated `dist` as source. If the host repository is available, consult `docs/v4/npm-content.md` and `docs/v4/effect-sdk.md`. Do not assume SDK packages have been published merely because a version is in a manifest.
2. Use `createEffects({ sdk, marks, id })` and `sdk.defineCodeEffect` for new behavior; use injected SDK objects and canonical prototypes. Keep `projectId`, namespace, use IDs and binding keys stable unless a breaking identity change is intended. Cross-package data references require npm dependencies.
3. Implement parameters with `numberParam`, `booleanParam` or `stringParam` when battle effects must read or modify them. Use the declared source scope and capture/follow semantics; do not require a parameter editing form. Keep per-battle state in engine instances, parameters and bindings rather than module-global mutable variables. Use the battle RNG instead of `Math.random()` for battle decisions.
4. Build and run the project's own scenario tests against the real engine. For a slow effect cover hit, miss, repeated application, removal and natural expiry; exercise supported waiting-point snapshot restoration if relevant. Preserve meaningful existing assertions and run independent host contract tests when available. The starter's `npm test` covers hit, miss, refresh, removal, natural expiry and restoration at a supported selection waiting point. Fix implementation failures rather than weakening unrelated tests.
5. Pack with `npm pack --ignore-scripts`, inspect the actual artifact and validate it in a separate npm installation. Installing, code admission and selecting a server environment are separate steps. Use the local development approval profile only for an explicitly approved local environment. Never treat a content hash, package install or client acknowledgement as permission to run code.
6. Use the project's available test and preview capabilities. The local author service's `preview_start` currently runs a real, headless demonstration battle from an isolated npm installation; it does not open an interactive battle or start multiplayer hosting. Distinguish this from existing trusted-draft interactive trials. Record the source and environment identities reported by the actual task. Keep active matches on their existing environment. The browser consumes server metadata, resources and battle state; it does not execute downloaded effect code.

For CLI/MCP operations, file conflicts and desktop project locations, read [tool workflows](references/tool-workflows.md). For media, locale and cross-package references, read [project sources](references/project-sources.md). The content library supports independent species, skills and marks; ability and emblem are mark tags. Authors can create objects, pick existing references, edit scoped multilingual names/descriptions, import media and preview bindings. Creation and field edits enter drafts and require reviewed saving. Drafts survive object navigation; shared YAML fields stay read-only in forms. Use external tools for TypeScript, file organization and intentional shared-definition edits.

When handed an `arcadia-author-context/v1` snapshot, use its `request`, `includesDrafts` and object access flags. Only `editable` objects are in the requested edit scope; `reference-only` objects explain relationships. Return a JSON suggestion file with `baseSnapshotId` matching the snapshot and a `proposals` array. Each proposal contains `key`, `target` (`record` or `locale`), a string-array `path`, and `before`/`after` values. Locale proposals also include a provided `language` and target `name` or `description`. Use the snapshot's exact before value; omit `before` for an absent field. Replace arrays as whole fields. Do not change IDs or shared YAML values. Do not invent a skill-to-mark field: effects connect those through actual behavior definitions and parameters. The author imports and reviews suggestions before they enter drafts and saves them separately. This handoff does not authorize direct source writes. MCP remains a separate project-wide capability, and cannot read unsaved desktop drafts unless the author includes them in a handoff.

Report the behavior changed, tests actually run, build/environment identity when available and any unmet validation. Publishing, registry credentials and deployment remain under the author's control; do not publish or deploy as a side effect of testing.

资源采用分离定义：规则位于 data/species、skills、marks；data/presentations 通过 target.kind/id 关联对象，用途字段引用稳定资源 ID；data/resources 定义 id/kind/source。不要把 presentation、assetRef/iconRef/sfxRef 写入规则。移动素材只改 source；表现、资源和语言同样需要版本检查、草稿保护及锚点保护。content_query 的 presentations/resources 可直接查询这些记录。
