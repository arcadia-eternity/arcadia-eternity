# 服务器交互与接口职责

本轮针对 PR #275 的游玩与托管入口。首页保留原对战大厅的布局、导航卡片、匹配和私人房间；原“在本机开服”按钮进入应用内开服配置。服务器独立为一级导航；内容库管理本地游玩内容，项目目录操作留在开发工具。

## 连接位置与服务器来源

顶栏显示真实对战连接：未连接时为“离线”；已连接时显示“本站 · 主机”“远程 · 主机”或经桌面主进程确认的“本机 · 主机”。准备连接的地址仅在连接详情中显示，不冒充已连接状态。首页移除重复的“当前地址”。网页与后端分开部署时按实际后端地址显示，不能把网页地址当成连接目标。

“官方／玩家”描述服务器运营来源，不是连接类型，也不构成权限或信任依据。默认入口标为“默认服务器”。玩家服务器同样可以直接用浏览器访问网址，或在桌面客户端输入地址连接。

网页只连接部署者配置的服务器，不显示地址选择器或切服动作。浏览器访问另一个网址属于打开另一个站点，不作为应用内切服功能。客户端才提供“用客户端连接”“在浏览器中打开”和独立的“管理登录”。

客户端本机开服同时提供配套网页，分享地址可用于浏览器访问或客户端连接。桌面运行时带有独立的 `web/` 资源；分发时排除后端运行时和临时 staging 目录，网页根目录不含这些材料。开发时需先执行 `pnpm build:web-distribution`。

## 用户流程

- 首次开服：首页 → 在本机开服 → 名称、玩法、连接范围 → 准备玩法 → 启动服务 → 邀请地址。普通开服无需选择文件或目录。官方玩法从随应用提供的内容离线准备；当前玩法必须已完成准备。
- 进入大厅是单独动作。开服、查看设置和管理服务器都不会改变当前游玩连接。切换本机游玩前，已有房间需要确认离开。
- 再次开服沿用服务器独立的身份、网络配置和玩法绑定。后续修改内容库的本地游玩选择不会替换服务器玩法。停止状态修改设置时，以仅本机修复模式启动，再进入网络设置；不以默认表单覆盖旧配置。
- 服务器页提供运行状态、邀请地址、管理概览、网络与容量、玩法与版本、停止和待应用设置的重启。管理页另有维护与备份、管理员与本服账户（按权限显示）。
- 正常停止等待现有对局结束。等待期间可明确确认立即中断；这会取消待执行的重启。离开页面不取消主进程操作。
- 远程游玩和管理分别在独立窗口打开。管理窗口不关闭游玩窗口、不自动连接对战。网页只连接部署者配对服务器；本机开服仅在桌面客户端可用。
- 首次失败保留当前页面表单；错误就地显示。已有配置启动失败可仅本机启动修复网络。复制地址失败时地址仍可手工选择。

## 接口检查与整理

原先托管可以经目录选择、内容库 start、项目 start、恢复和停止多个 IPC 入口进入同一个宿主。UI 要自行组合准备、启动、确认切服与状态读取，容易把“开服”误做成“选项目”，也容易与内容选择混在一起。

现在使用以下边界：

| 职责           | 入口                                   | 约束                                                                                           |
| -------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 托管生命周期   | `localServer({ action })`              | 主进程 `LocalServerController` 串行处理普通及项目启动、停止、恢复、重启；状态轮询不产生进程    |
| 首次开服配置   | `start.configuration`                  | 只接受名称、玩法来源、连接范围、端口、公网 origin；不接受路径、命令或执行文件                  |
| 项目开发启动   | `start-project.projectId`              | 只接受已登记 ID，服在运行时先要求停止；与普通开服共用操作互斥                                  |
| 持久服务器配置 | ManagementService settings             | CLI 私有启动参数先校验，再经现有 revision-checked PATCH 保存；没有第二套配置文件或 HTTP 写接口 |
| 内容材料与租约 | ContentLibrary / DesktopWorkspaceOwner | 宿主借用材料；首次准备不更改本地游玩选择；保存绑定继续独立持有版本                             |
| 当前游玩连接   | `enterLocalServer()`                   | 只在用户明确进入时授权、确认离房并切换；管理不调用                                             |
| 远程窗口       | `openRemotePlay({ url, mode })`        | play / management 明确区分，均使用应用内置页面和独立临时会话                                   |

已有 HTTP 管理资源、权限、revision 冲突保护、持久操作记录保持同一合同。`getLocalBattleStatus` 仅因桌面连接授权需要而保留，不提供写入。内容库和项目管理不再通过自己的 Renderer IPC 发起宿主启动；内部材料管理接口仍服务既有测试及开发工具。

## 验收重点

首次官方玩法与已安装玩法真实启动、持久设置与绑定重启恢复；内容准备失败不启动宿主；并发启动去重、排空与强制停止；管理窗口不会关闭游玩窗口且不获得本机权限；桌面和移动宽度的开服入口无需文件选择；服务器设置冲突保留草稿；导航调整后连接偏好和备份下载继续有效。

本轮源码验证不代替安装包、签名或跨平台发行验收。
