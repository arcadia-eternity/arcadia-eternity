# TypeScript 效果的 Arena / Comlink 执行宿主

此实现接续 [#218](https://github.com/arcadia-eternity/arcadia-eternity/issues/218) 和 [#269](https://github.com/arcadia-eternity/arcadia-eternity/issues/269) 的实验。对局使用独立 Worker，每个内容包在该 Worker 中拥有独立 QuickJS Runtime、Context、WASM 内存和 Arena。Worker 不复用，模块可变状态不跨局共享。

## 分工与入口

- `@arcadia-eternity/battle/v4/sandbox`：Arena 效果模块、Worker 管理器及 TypeScript 合同。
- `@arcadia-eternity/battle/v4/sandbox/node`：Node Worker 工厂；浏览器使用静态 `sandbox/worker` 入口，由 Vite 打包。
- `quickjs-emscripten-sync` 的 Arena 负责 VM 内外转换、代理及句柄；Comlink 负责主线程与 Worker 的异步调用和事件。没有自定义 RPC 协议、通用对象编码器或 Map/Set 同步实现。
- 原生引擎和 SDK 在 Worker 内执行。作者模块顶层、`createEffects`、`build`、自定义计算及回调在其包的 VM 内执行；同一个引擎调用栈中的 SDK 调用与回调同步重入。

`compileEffectModule` 使用固定 Rolldown 配置将 TypeScript 和依赖编译为封闭 ESM 文本，不执行作者顶层代码，不读取作者插件配置。依赖真实路径必须位于捕获的安装目录内；Node 内建模块、远程依赖和残留运行时 import 被拒绝。SDK 导入替换为宿主能力入口，避免打包出另一份引擎。

内容包只发布普通效果模块和元数据。基础包的唯一效果入口为 `@arcadia-eternity/data-pack-base/effects`，导出 `createCatalog`、`createEffects` 及供可信工具使用的参考函数，不包含 VM 制品或执行器。宿主从普通模块选取效果工厂，复用 `compileEffectModule` 准备 VM 源码；未使用的宿主辅助导出被剔除，作者模块初始化仍在 VM 内执行。浏览器、CLI 和服务端的构建由宿主插件嵌入编译结果，TypeScript Node 源码启动则由宿主即时编译。

`prepareNpmProject` 只读取数据、校验 schema／静态引用并编译封闭的效果源码，返回只读数据索引和深冻结的 `sandbox` 配方，不创建 VM、不执行模块顶层或工厂。官方包的生产加载器也使用静态索引和同一配方。实际对战在新 Worker 中创建全部 VM，并检查实际导出、工厂和绑定。客户端数据／资源加载使用 `PackMetadataLoader`；官方效果 ID、模板说明和关联表来自构建生成的静态 `data-pack-base/metadata`，不构建可执行目录。

基础包的 `watch:code` 更新普通 `effects.js` 和构建身份；宿主插件监听编译实际读取的依赖，将更新传播到 CLI／服务端 watch 和浏览器开发服务。依赖出现语法错误后继续监听，修复后重新编译。包内不再生成 `sandbox.js`，无需额外生成任务。CLI 发布目录同时包含静态 Worker 入口及其依赖，搬迁后仍可离线对局。

普通服务端、发布版客户端和未进入编辑模式的对局只使用准备好的固定制品，不监听或轮询源码。服务端显式准备 npm 环境时编译一次并捕获内容，之后修改源文件不会更新已准备的环境。只有显式启动 watch、开发服务或编辑会话时才监听；一次性生产构建也不登记监听依赖。

## 必要的 SDK 适配

`ArenaEffectSdk` 只处理本项目的 SDK 能力与身份：

- 注册 SDK 创建的参数、选择器、计划和效果导出，保留原生身份，使既有 WeakMap 注册和参数地址继续有效。
- 对领域对象提供实时只读字段；同一精灵或印记在多次调用中对应同一对象。状态变更使用 SDK 操作，或明确列出的领域方法（治疗、伤害、怒气、印记操作及本局 RNG）；不暴露调度器、进程对象或私有成员。
- 调用上下文、frame 和其操作只在当前同步回调内有效。回调结束注销临时注册，之后读取或调用会锁存故障；领域身份保留到该局销毁。
- 自定义回调必须同步，不接受 Promise。模块没有 Node、DOM 或网络能力；默认时间固定为零，`Math.random` 拒绝调用，随机结果从本局 RNG 取得。
- Map/Set 沿用 Arena 的值传递语义；内容目录的成员集合在本局固定，不提供通用集合变更同步。

原生 SDK 的全部基础设施 API 并非沙箱能力。直接构造领域实例、写领域字段、低层属性系统或自定义订阅应改用已有选择器、`ops`、参数和绑定工具；未适配的访问会失败，不会返回裸宿主对象。领域方法和公开字段的允许列表集中在 `sdk.ts`。

## 管理与故障

`BattleWorkerManager` 负责准入、启动、外部看门狗、取消、清理及有界状态记录。默认最多 4 局（含准备中），启动期限 20 秒，单次控制调用 5 秒，清理 1 秒，每秒健康检查。完成等待不受单次调用期限限制；健康检查仍继续。槽位在 Worker 实际终止后才释放。

VM 默认堆上限 128 MiB、WASM 上限 256 MiB、栈 512 KiB；初始化或工厂调用 10 秒、普通同步调用 500 ms，并限制调用次数、保留对象、包数、代码和输出大小。每个根调用共享重入期限和计数；还会执行并限制脱离调用的微任务。具体常量以 `contracts.ts` 为准。VM 内存限额不等于整个 Worker 或进程的 RSS 上限。

VM 故障锁存在模块；原生 execution budget 观察模块健康，阻止引擎在吞掉作者异常后继续结算。管理器遇到故障、Worker 退出或超时后终止该局，拒绝挂起调用。没有原生重跑、回滚、自动判胜或 Worker 复用。清理诊断区分正常释放与超时／异常后强制终止。

事件保留原生订阅的视角与隐藏信息规则，队列和单条消息有上限。输入事件在控制调用返回前送达，供 CLI 记录动作。管理器共享的仅是控制和诊断信息。

## 产品接入与持久化范围

浏览器本地对战与 P2P 主机、作者调试试玩、CLI 和服务端的官方及获准 npm 环境均使用该 Worker 宿主。原生参考函数仅用于可信引擎测试。官方服务的第三方代码准入策略保持原有边界。

开发工具的 `await testing.createBattle` 仅保留为可信进程内引擎检查工具，按局创建 VM，随该局 `cleanup` 释放；`contentFor(battle)` 提供该局的快照和参数检查，`await restoreBattle(snapshot)` 在新 VM 中恢复。不提供进程外看门狗。产品对局和自动调试均使用 `createBattleSession`。作者测试本身是用户授权执行的 Node 程序，不能视为不可信游戏代码的入口。

官方与 UGC 内容沿用同一个等待点快照合同：保存领域状态、参数、RNG、稳定引用和已注册的绑定；恢复时在新 Worker 中加载相同代码，重建目录、效果和绑定，再恢复原生对象及其关联。快照不包含函数、VM 堆或任意模块变量，不增加包级开关。不能由现有 SDK 重建的状态仍由原生快照校验拒绝。

CLI replay 保留开局前快照和输入记录，在新 Worker 中恢复初始状态并重新执行。初始输入校验在宿主内完成，只返回普通数据，不暴露原生 Battle。npm 沙箱目录身份同时覆盖捕获的代码制品；本地代码可以继续编辑，但旧快照与 replay 会拒绝不匹配的代码。

## 验证与剩余边界

自动化覆盖真实 SDK 身份／参数、自定义同步计算、最新状态读取、原生治疗和 RNG、过期上下文、捕获异常后的故障锁存、无限循环及微任务、编译路径与 import 拒绝、跨包／跨局隔离、取消和并发限制。官方完整效果目录在真实 Node Worker 中运行，与原生固定输入驱动逐等待点比较；另测新 Worker 中恢复官方等待点后继续执行。

2026-11-04 入口、快照／replay 验证：各包回归合计 1611 项通过，服务端另有 14 项原有跳过。其中引擎 680、加载器 71、CLI 63、作者工具 101、Web 541、服务端 116；其余为 schema、client 和 P2P transport。另有 6 项 CLI 兼容测试和 88 项作者接口设计回归通过。真实 UGC 的参数跟随、自定义绑定计算在新 Worker 恢复后数值一致，印记自然到期后属性还原；独立进程 replay 包含队伍预选，并拒绝篡改初始输入和修改后的代码。目录搬迁不改变代码身份；初始状态校验返回的属性记录与引擎对象隔离。

普通入口的宿主编译覆盖辅助导出剔除、作者初始化保留及依赖语法错误恢复。实际同时监听基础包和 CLI 宿主，将 TypeScript 治疗量从 90 临时改为 91 后，VM 中 HP 从 110 变为 111；还原源码后恢复为 110。CLI 发布目录搬迁后无须 workspace 依赖即可运行官方 Worker 对局；启动中取消、动作上限和终端输入释放均通过真实进程回归。真实 Worker 的就绪、动作提交、快照调用挂起时取消均返回取消结果并释放 Worker。禁止文件监听接口后，生产服务仍完成启动、健康检查和关闭，监听调用计数为零；离线对局和 replay 也通过同样检查。

全量回归按包串行执行；服务端和 Web 的整包复验使用 `--testTimeout=30000 --hookTimeout=30000`。多进程 replay 和大型目录清理测试使用各自的等待时限；房间启动测试与客户端默认 30 秒等待一致。这些调整不改变生产 VM 或 Worker 限额。

准备流程清理复验：加载器 78、Web 541、服务端 116 项整包通过，服务端保留 14 项原有跳过；作者工具 101 和 CLI 63 项覆盖分组复验通过。静态索引／合同的 22 项定向测试及作品链接的 13 项测试通过。完整引擎与 CLI 运行曾出现间歇 VM 预算／测试时限失败，受影响场景隔离复验通过；没有放宽生产限额，也没有增加旧 replay 的兼容、迁移或兜底重跑。

浏览器本地启动、队伍预选和延迟资源启动 3 项再次通过；压缩 Worker 回归实际执行 `ParameterCatalog`、`HealContext`、`Pet instanceof` 和治疗事件。官方差分比较本例逐等待点的回合、阶段、状态、HP、怒气和印记，不代表全量事件轨迹验收。

这些测试不替代 #269 的完整安全验收。全部历史差分样本、长期 RSS／句柄压力、恶意依赖完整矩阵、平台级进程故障隔离、正式安装包及跨平台运行仍需单独验证。Worker 可以隔离普通 JS 执行和可终止的故障；整个进程的致命故障仍需要部署层进程边界。
