# 服务器管理与离线环境库：交互方案

状态：已实现第一轮管理台与离线环境库，验证记录见文末。延续现有首页和顶栏；本轮只调整管理内容。

## 已确认边界

- 环境管理放在“内容包 → 环境”，与已安装内容包并列为页签。
- 环境可以离线编辑和保存，不要求启动对战服务器。准备版本在材料齐全时可离线执行；缺失材料展示待下载项，不把“保存草稿”阻塞掉。
- 一个服务器同时维护和运行多个环境。默认环境只是新建对局的预选项，不是运行互斥开关。
- 环境草稿、固定版本、服务器上的使用关系分别拥有状态。编辑本地环境不会自动改变服务器。
- 玩家服务器可通过网页地址直接访问，也可由桌面客户端连接。网页仍只连接部署者配置的服务器。

- 1Panel：https://1panel.pro/docs/v2/user_manual/websites/websites/ 。借鉴多个站点的资源管理分区；不套用一个服务只对应一个玩法的模型。
- Prism Launcher：https://prismlauncher.org/wiki/getting-started/create-instance/ 。借鉴独立组合的创建、编辑入口，应用在离线环境库。

## 导航与状态

内容包：已安装 / 环境 / 创作项目。环境库采用列表和详情，显示草稿、准备好的版本及发布去向。明确当前操作属于本机环境库；远程服务器自己的环境材料不隐式与本机同步。

服务器管理：概览 / 运行环境 / 网络与容量 / 操作记录与备份 / 访问权限。

概览显示被管理服务器的名称与地址、管理连接、接纳新局状态、已开放环境列表和待处理事项。游玩连接继续留在应用顶栏。

运行环境默认展示所有环境而非单选器：名称、版本、状态、匹配/房间可用性、默认标记。支持添加环境、更新版本、配置开放方式和移除。暂停接纳应按环境作用，并说明已有对局的处理；全服排空始终是独立操作。实现前核验底层禁用语义，不能直接把 enabled=false 包装成“等待对局结束”。

环境详情显示当前版本、可发布版本与差异、更新记录。更新前说明对本环境新房间的影响及旧房间保留旧版本，其他环境不变。缺材料、权限不足、版本冲突在当前操作中提示。默认环境不可在未选择替代项时删除。

网络与容量分成常用网络配置和高级性能/跨域设置。区分实际监听地址、保存的配置、待重启配置；自动端口 0 不得显示成实际端口。远程管理不提供无保证的进程启动按钮。

备份和后台任务集中显示状态与错误，准备、发布、备份可离页继续。权限按服务能力呈现，服务凭证与玩家身份保持独立。

## 当前源码差距

- ManagementService 已有多个 bindings 和 defaultBindingId，无需将服务器模型收窄为单环境。
- ContentManagerPage 的“环境与服务器”按钮目前直接嵌入整个 ManagementConsole，需拆成内容包内的环境页签。
- desktop:management-request 当前转发 LocalBattleHost，宿主未运行时拒绝请求。本地离线环境需要独立 workspace 服务生命周期与持久化入口，不能后台偷偷开服。
- 复用现有环境文档、固定版本、revision 冲突保护与材料租约；避免另建不兼容的第二套环境格式。
- 跨本地/远程发布需要显式传输固定版本和材料，校验后由目标服务器发布；不把本机路径或版本 ID 当作远程已存在的材料。

## 验收场景

1. 服务器停止且断网时创建/修改环境草稿，重启客户端仍保留；全过程没有启动对战监听。
2. 同一服务器同时开放标准与自定义环境，设为默认不关闭另一环境。
3. 修改草稿不影响两个运行环境；只更新其中一个时，另一环境及已有房间不受影响。
4. 内容不齐全时草稿仍能保存，准备版本明确列出缺失材料。
5. 远程发布中断、revision 冲突和权限拒绝保留编辑内容并可重试，不显示虚假的成功。

原型中的每环境房间数、管理状态摘要和离线编辑为目标交互，不代表已有接口完整支持；实现时补齐统计口径与工作区边界。当前默认绑定不能被直接禁用，界面需提示先选替代默认环境。

## 本机库与服务器副本

服务器自己的工作区仍支持维护多个环境草稿和版本。运行环境详情提供“编辑服务器副本”，进入明确标记该服务器工作区的环境编辑视图；它不伪装成本机草稿，不隐式同步。内容包内的本机环境页保持独立离线工作。网页端只提供当前部署服务器的授权管理视图，不能通过工作区选择变相切换游玩服务器。本机版本发布到远程后，保存其发布去向用于追踪，后续两侧编辑均需显式更新。

## 用户管理与活跃对战

这两项作为服务器管理一级导航，位于“运行环境”之后。

### 用户管理

- 在线玩家：包含本服账户与游客，显示连接状态、当前对战；用户详情链接到关联对战。
- 本服账户：显示账户状态与详情。管理员授权、自动化凭证保留在“访问权限”，不与玩家身份混为一谈。
- 停用账户前显示影响：本服登录受限、现有连接撤销、对战按断线规则处理。确认后执行，处理记录自动包含操作者、目标、时间与结果，不要求输入原因。
- 不把现有 deactivation 描述成可恢复的临时封禁；恢复、定时封禁、单会话踢出不是已有能力。
- 游客没有可停用的本服账户。身份标识属于该服务器，不能据此管理其他服务器账户。

### 活跃对战

- 默认跨所有环境汇总，按环境与对战状态筛选。显示参战玩家、环境固定版本、已进行时间、状态，以及服务器执行或玩家端执行。
- 当前运行版本取自对战自身，不能跟随环境发布后的最新版本而改写。
- 单场详情链接参战玩家与环境。显示连接中断/恢复等诊断事件，不自动暴露未公开决策、阵容或其他对战私有信息。
- 单场终止是明确的管理员中断，确认后执行，自动记录操作者、对象、时间与结果，不指定胜负，不影响其他对战；正常结束与管理员终止发生竞态时以后端真实状态为准。
- 玩家端执行的对战不显示服务器没有能力取得的回合进度，不承诺服务器能够直接结束玩家端计算。
- 全服暂停接纳新局仍在概览，不与单场终止混用。

### 接口现状与实现工作

现有 ManagementAccounts 支持本服账户分页列表、详情与停用，停用沿用账户撤销/断线路径。在线游客/会话汇总、账户搜索和处理记录需要补齐相应合同。

当前管理 API 只暴露房间总体状态和全服排空，没有完整的管理员活跃对战列表/详情/单场终止入口。需增加按环境分页的稳定快照、连接与对战状态、明确的读取/终止权限、幂等处理及审计。既有账户管理权限不自动获得结束对战权限。原型演示的是目标交互，不代表这些接口已经落地。

## 本轮实现与明确边界

- 内容包内增加“环境”页签。独立本机工作区支持离线创建、编辑、复制、删除草稿，准备/取消版本、查看引用、删除版本及环境文件导入导出。材料下载默认关闭；同名导入不会覆盖现有草稿。客户端退出会取消未完成任务，草稿与固定版本持久保存；本地任务列表保留本次客户端运行的最近 30 项。
- 服务器管理使用侧栏导航，优先展示运行环境，再展示服务器环境库。原有多环境绑定、发布版本、默认环境、开放方式、跟随更新、移除绑定、排空与恢复接纳功能保留；默认环境必须先指定替代项才能停用或移除。新增带 revision 保护的草稿删除入口。
- 活跃对战与玩家会话使用独立读取权限及有界分页接口。对战记录从房间租约捕获环境名称、绑定和固定版本；发布后已有房间不会被改写。列表按标识游标分页并自动刷新，不是跨页事务快照。
- 单场服务器对战确认后即可终止，不要求输入原因；操作具备幂等键、提交前权限复验、审计与后台任务结果。终止不指定胜负，玩家收到管理员中断提示。玩家执行模式不提供强制结束计算按钮。
- 用户页提供在线访客/账户会话、搜索、关联对战及账户状态、分页加载与停用确认。账户创建沿用本服登录注册；停用沿用既有撤销路径，当前没有恢复、临时封禁或物理删除功能。
- 网络页区分实际监听端口与保存的配置；权限页和管理登录页说明主机初始化及账户授权。最近管理操作展示当前服务器最近 200 条审计摘要。
- 本机和服务器之间通过包含材料的环境文件显式导出/导入，导入后再开放版本。自动同步、发布去向追踪、版本差异对比、诊断事件时间线及离线环境直接启动试玩尚未在此轮实现。

## 首个管理员与恢复访问

管理员由显式权限授予决定。玩家注册不会自动获得管理权限，也不采用“首个玩家即管理员”。纯服务端的部署者在服务器主机执行：

```sh
node dist/cli.js server admin login-code --data-dir /path/to/server-data
```

使用服务器实际的数据目录；自定义内容工作区时追加相同的 `--workspace-root`，外部数据库使用与服务进程相同的存储配置。返回的 `code` 默认 10 分钟有效且只能兑换一次。在管理登录页兑换后建立 Owner 会话，拥有该服务器及工作区的全部管理权限。可在“访问权限”创建关联本服账户的管理身份，再授予所需角色。重新执行主机命令也可恢复访问。桌面可信本机窗口走受限制的 IPC 授权，远程网页不能调用这些本机接口。
