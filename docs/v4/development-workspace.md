# 本机开发工作区

服务器默认不提供源码编辑接口。管理员只有显式配置 `development: { directory, token }`、将服务绑定到 `127.0.0.1` 并指定非通配的允许来源时，才启用该接口。令牌由管理员本地配置，长度为 32–256 字符；它独立于玩家会话，不出现在目录响应、URL 或日志中。应使用随机生成的秘密，并通过安全渠道向开发客户端提供。

使用 CLI 时，先在当前进程环境中设置 `ARCADIA_DEVELOPMENT_TOKEN`，再运行：

```sh
node dist/cli.js server --host 127.0.0.1 --development-project /path/to/source-project
```

默认允许本机开发网页来源；如网页使用其他来源，应通过 `--cors-origin` 显式指定。令牌不要写在命令参数中，也不要放进可分享的项目文件。进入网页的开发工作区后，填写本机服务地址与令牌即可读取源码。

`GET /api/v1/development/content` 和 `PUT /api/v1/development/content` 使用 `Authorization: Bearer <令牌>`。服务只读管理员选定的 npm 源项目中的固定 `package.json` 和 `content.json`，禁止符号链接和超限文件；接口不接受路径。GET 将完整 `content.json` 返回给持令牌的开发客户端，包括自定义字段；不要在该源码文件放置凭据或私人数据。返回 `{ revision, content, project }`：revision 是 content.json 字节及项目 ID、namespace、Effect 导出列表共同计算的 SHA-256，用于检测编辑保存冲突；project 包含项目 ID、namespace 和包声明的 Effect 导出。导出列表只表示源码声明，不证明代码可运行或已准入。

PUT 接受 `{ revision, content }`，校验旧 revision 和完整 JSON 对象，将结果原子替换原文件。调用者应基于 GET 返回的完整对象修改所需字段，保留未展示的内容。服务通过项目内 `.arcadia-content.lock` 串行化配合该锁的写入，并再次检查文件和包身份；过期修订返回 409 `REVISION_CONFLICT`，锁已占用返回 409 `DEVELOPMENT_BUSY`。若进程异常退出留下锁，应先确认没有写入进程再手动删除它。

对不使用此服务或锁协议的编辑器，服务会检测读取或写入前已经发生的变更，但普通文件系统不提供与任意外部编辑器共享的原子比较并替换。外部编辑恰好发生在最后一次检查与重命名之间仍可能被覆盖；要获得严格并发保护，AI 和其他编辑器必须使用同一服务或遵守该锁协议。此基础接口尚未提供开发构建、自动准入或预览启动，保存源码不会改变已发布环境或活动对局；需要单独构建、检查并准入新的固定环境后才能试玩。

开发目录必须由可信本机用户控制。接口拒绝静态符号链接、检查目录身份并在检测到替换时失败；Node 的跨平台文件 API 不能消除恶意同账户本地进程在路径检查与文件操作之间替换父目录的竞态，因此这不是对该类本机攻击的隔离边界。

编辑精灵时，可直接选择本包尚未发布的技能和印记；也可按需读取当前服务器的公开环境，从中选择官方或其他包的技能与印记。公开内容中的命名空间对应环境目录里的包身份，读取不执行效果代码、不发送开发令牌，也不会改变服务器环境或对局。已有引用和不认识的字段仍会保留。环境目录不提供源码项目的 npm 依赖关系，因此选择其他包的内容并不代表引用已验证：需在源码包声明相应 npm 依赖，重新构建并通过内容验证。环境发生变化时，应重新读取并选择适用的内容。
