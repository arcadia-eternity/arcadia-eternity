# 内容调试窗口与编队委托验收（2026-11-02）

## 交互与数据边界

- 工作台常驻“调试试玩”，候选准备完成后自动打开独立调试窗口。检查、场景测试、无界面演示和打包保留在次要运行面板；任务状态使用中文，底层输出与来源折叠。
- 调试窗口先配置我方及 AI 对方测试队伍，再开始战斗。测试配置从项目默认队伍复制，在候选专属的非持久 Electron Session 中保存；重新打开同一候选保留配置，不同候选分开，应用退出后释放。
- 既有编队 UI 提取为 `components/team/TeamEditor.vue`。`TeamEditorDelegate` 提供队伍引用、就绪状态、持久化和增删操作；仓库、导入、导出与清理是可选能力。个人页面的 `personalDelegate` 使用既有个人存储，`previewTeamDelegate` 只操作测试队伍。共享组件不依赖个人存储，也不判断试玩模式。
- “返回编辑器”关闭调试窗口并恢复原编辑窗口，保留其位置和当前候选。“继续当前对局”与刷新接回已有运行状态；结束后重新打开也显示原胜负。战斗中的“结束并调整队伍”确认后回到配置，可以重新开始。
- 独立 `AuthorPreviewShell` 不初始化主应用的个人身份、仓库和完整默认数据；候选页安装公开内容，战斗页负责场景与素材就绪。打开窗口使用固定背景，准备页与战斗页共用加载组件。
- 宿主配置接口在成功验证并构建新队伍后才释放旧对局。非法引用保留旧对局；测试配置不会改写项目默认配置。
