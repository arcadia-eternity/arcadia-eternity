# Official parameter surface audit

`scripts/effect-migration/parameter-surface.mjs` compares every current source `raw:*` node with the compiled native catalog. Each source node must map to one address in its own effect namespace with the same default and tags. Explicit legacy aliases must resolve to that same address. Anonymous nodes are matched only when their value/tag signature is unique within their effect; ambiguity and address reuse fail rather than guessing. The source file, definition hash, definition pointer, value-node pointer and native address are recorded in `official-parameter-mapping.json`.

The audit found four missing declarations: the true/false amounts in the 120/60 and 125/63 consecutive-healing effects had been converted to literals. Their default-only comparisons passed while parameter edits were lost. Both effects now reuse `numberParam`, `values.choose`, the shared owner query and heal operation. They retain the source's branch direction. Each branch has its own stable address and is read in the current source scope at action execution; the unselected branch is not read.

The added 20 runtime cases first failed against the literal implementation. They compare unmodified legacy definitions and independent amounts for Skill/Mark sources, first/repeated uses, zero/fractional/negative configuration, foreign source scopes, edits after admission and fresh-host snapshot restoration. Negative amounts remain visible to the HealContext before its existing zero clamp; the runtime rules are unchanged. Existing consecutive-healing cases continue to test actual skill counts, hooks, reset and restoration. The combined new/default/weakness/native-content run passes 125 tests; V4 types, lint and declarations pass.

The final declaration mapping contains **139 source raw nodes, 25 explicit aliases and 145 native parameter addresses**. All original nodes map one-to-one. Six additional native parameters expose former literals for trusted configurable definitions; they are explicitly listed in `official-parameter-extensions.json` with defaults and reasons. They are distinct from original raw declarations. An unlisted extra, missing declaration, changed default/tag, foreign alias, shared address or stale extension fails the gate. Four verifier regressions cover those failure modes.

Repeat with `pnpm verify:battle-v4-parameters` after building battle. The check is included in the battle workflow. `node --test scripts/effect-migration/parameter-surface.test.mjs` checks the verifier's rejection behavior. This audit verifies the declaration surface; it does not replace per-effect execution, capture/follow, Config lifetime or alias-interaction tests.

Independent `code-review` axes: Standards, zero findings; Spec, zero findings. Standards found no documented-rule breach or actionable baseline smell. Spec confirmed the four parameters' identity/timing/scope, the characterization-only weakness changes and the verifier's limited declaration claim; its separate rerun of the four verifier cases and complete parameter check passed. The complete fixed-build regression remains a separate gate.
