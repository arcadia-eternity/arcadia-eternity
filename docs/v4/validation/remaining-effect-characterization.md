# Final five source behavior checks

The unchanged parsed YAML definitions were executed by `remaining-effect-characterization.test.ts`. All five checks pass against the current V4 legacy adapter. These are observations, not completed native candidates.

| Effect                                                | Observed execution                                                                                                                                                                                         | Repository description / proposed correction                                                                                                                                                                 |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `effect_mark_special_damage_reduction_with_stack`     | `selectAttribute$('stack')` returns a reactive source object. `GetValueFromSource` returns the selector output unchanged; `addModified` produces `0[object Object]`, then damage calculation produces NaN. | `packs/base/locales/zh-CN/mark.yaml`, 沙之网: subtract stack from Special damage. Read the numeric current stack and negate it.                                                                              |
| `effect_skill_add_damage_30_per_niliu`                | `AfterUseSkillCheck` receives a UseSkillContext, so the damage-context selector is empty. A later damage trigger does not admit this effect.                                                               | `packs/base/locales/zh-CN/skill.yaml`, 逆行反击: add 30 fixed damage per 逆流 layer. Move the modifier to the damage calculation trigger.                                                                    |
| `effect_mark_limit_rage_gain`                         | BeforeRageGain writes the initial zero result. RagePhase then recomputes the result: an attempted 20 gain with stack 3 still grants 20.                                                                    | `packs/base/locales/zh-CN/mark.yaml`, 心灵制约: cap each actual gain at current stack. The cap must participate in final rage calculation.                                                                   |
| `effect_mark_prevent_rage_loss_on_switch`             | Actual SwitchPetPhase directly sets rage to floor(80%); no BeforeRageLoss hook runs. Starting at 100 ends at 80, and the protection mark remains active.                                                   | `packs/base/locales/zh-CN/mark.yaml`, 飞旋阵: no switch rage loss. Route switch loss through the existing rage operation and preserve outgoing-owner context. Existing source actions also destroy the mark. |
| `effect_ability_add_20_rage_when_use_fly_skill_twice` | Parsing the `lastSkillId` selector fails. Current skill execution overwrites `Pet.lastSkill` before all skill hooks, so merely renaming the path would still read the current use, not the previous use.   | `packs/base/locales/zh-CN/mark_ability.yaml`, 飞翔: consecutive Flying uses restore 20 rage. Preserve previous-use information and keep the source's OnHit timing.                                           |

The parser, selector, modifier, rage and switch mechanisms already exist. V2 also has last-skill ID storage plus an object alias and ancestor switch-context support (see `historical-cross-version-findings.md`). None of these observations establishes that the engine lacks the corresponding general capability.

The user approved all five proposed corrections, including the Flying consecutive-use interpretation and the switch mark's one-use action. The stack-damage candidate ledger now covers the first two; rage capping, switch protection and previous-use history remain to be implemented. These unchanged legacy tests remain as correction evidence.
