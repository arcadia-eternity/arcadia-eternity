Its legacy `checkSelf` only admits damage-origin rage under a skill context, and assigning `rageChangeResult` before settlement is overwritten by the existing recomputation. The characterization test now starts an admitted event with provisional result 10, observes the legacy clamp to 3, then observes actual gain 20. `RageContext.limitGain(maximum)` records an event-local finite non-negative limit. Multiple limits compose by minimum. `updateRageChangeResult()` applies all percent/delta modifiers, applies the gain limit, then floors the result. Without a limit, existing arithmetic is unchanged. Reduce and setting operations are unaffected. This is an explicit user-approved runtime correction, recorded in the source provenance hash; the source YAML is preserved.

The authored API exposes `ops.limitRageGain(value)` with the existing numeric-input evaluation and cross-battle validation rules, and `conditions.ownerReceivesRage` for direct rage events targeting the source pet's player, regardless of reason. The official effect reads the source mark's current numeric stack at action time. It stores neither a persistent binding nor a later re-evaluation callback: subsequent stack changes affect the next event only.
