# Stat stage clearing candidates

All ten independent clearStatStage definitions now have generated candidates, with zero rejections and no source corrections. BeforeHit and the exact BeforeHit/OnMiss pair retain their source identity. Missing strategy defaults to positive; omitted or empty stats means atk, def, spa, spd and spe in that order. Explicit stat order and duplicates are preserved. Special defense (spd) and speed (spe) remain distinct.

The typed clearStatStages API snapshots declaration options and removes matching stage marks through the existing removal lifecycle. It does not overwrite a pet's attributes or bypass destruction callbacks. Stage sign is checked at removal time; indestructible marks remain. Source-owner and opposing-active-pet queries run at execution, after admission.

Standards review reproduced a boundary defect in the first adapter: one pet.clearStatStage call could remove several attributes, and an earlier destruction callback could transfer that same pet to another battle before later attributes were removed. The domain traversal was extracted into Pet.getClearableStatStageMarks. Both the original domain method and authored adapter reuse this lazy iterator: each stat snapshots its members when reached, and each member's current level is tested immediately before yielding. The authored adapter revalidates the Pet and Mark before each removal. Already completed removals remain committed; later foreign writes are rejected.

Public differential tests cover both skill and mark sources, mixed/all-positive/all-negative/zero stages, exact spd/spe selection, support removal after admission, late sign/owner/slot changes, cancellation, indestructible marks, nested and repeated execution, and real hit/miss SkillPhase dispatch. selfUseSkill intentionally resolves an ancestor skill context, so nested events remain eligible. Operator tests cover default/all/empty selection, option snapshotting, callbacks changing later levels, initial foreign targets, a later pet becoming foreign and the same pet becoming foreign between attributes. Direct domain tests independently establish that callback additions to the current stat are outside its snapshot while additions to a later stat are queried.

The final three-suite regression passes all 396 public checks. Ten focused lifecycle checks also pass, including two subsequently added domain snapshot tests. All 133 generator tests, 75 design tests, V4 types/lint and declarations pass. Both review axes approved the core extraction and ownership fix; provenance was refreshed only for pet.ts and verifies successfully. Existing generated catalogs reproduce unchanged.

## Standalone negative-stage reversal (2026-10-20)

The catalog now also includes `effect_skill_reverse_self_negative_stage`, bringing it to eleven candidates with no rejection. The shared action emitter admits `reverseStatStage` independently of mark-resource factories; it uses the existing `ops.reverseStatStages` API and introduces no runtime or source YAML change. The effect queries its current owner at execution and reverses only then-negative stages, preserving the distinct `spd` and `spe` attributes.

The public matrix now includes the new effect for both Skill and Mark sources across all sixteen existing scenarios. Independent expected-level and destruction-event assertions distinguish reversal from clearing. In particular, an indestructible negative stage survives removal. Adding its opposite reaches the zero-stage stacking path, which attempts removal again without assigning level zero. The original negative level therefore remains; this existing behavior is preserved explicitly. Repeated calls, late owner/level changes and actual hit/miss phases remain differential checks against the unchanged legacy definition.
