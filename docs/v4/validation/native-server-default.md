# Native server default

New server battles now select `native-v4` by default in `LocalBattleRuntimeFactory`, including the default rule-configuration fallback. Explicit `legacy-v2` creation remains available for historical recovery. Recovery always selects from persisted identity before construction, so untagged historical records retain their original V2 rules. The native factory tests reject any accidental call to the legacy creator.

Cluster-room creation initially stores a waiting room without a guessed bootstrap. The complete native initial state is persisted before the local instance is published. Activation reads the persisted room again before changing its status; spreading the original temporary room would overwrite the newly saved native descriptor. A test uses independent read/write copies, as Redis does, and recovers the activated room through metadata after deleting its Redis bootstrap. The original instance identities remain intact.

The original 21 V2 service assertions now request their implementation explicitly. Native service fixtures use the default creation path. Additional cases prove the factory default, complete cluster-room creation/activation, metadata recovery and abandonment after a real native turn. This exposed an unowned five-second BattleEnd cleanup timer; room/service cleanup now cancels it, and stale end handlers cannot schedule cleanup for a replacement instance.

Validation on 2026-10-23: all **59 native-factory and service cases pass** inside the full server run. The full server suite reports **142 passed, 2 failed across 19 files**. Both failures are the existing local/remote dual-disconnect expectations in `clusterBattleServer.disconnect-healing.test.ts`. Running that file in an independent archive of pre-cutover commit `09f7757c6072850d9026332e61e643b1f3a88a41` reproduces the identical two failures. Their assertions and production source were not changed. Source/test types, native server lint, server code and declaration builds pass.
