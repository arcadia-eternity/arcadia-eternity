# Bounded UGC content packs

`compileContentPack(unknown, trusted?)` now builds an isolated candidate containing authored standard marks, generated add-mark actions, and skill/mark rules. The runnable saved example is [ugc-recovery-pack.json](../examples/ugc-recovery-pack.json).

Each mark retains an ordered list of stable Effect IDs. All local definitions use the pack's `id/` prefix; this is collision hygiene, not proof of account ownership. Mark rules must belong to exactly one declared mark, skill rules cannot occupy mark effect lists, and saved sourceMarkId must agree with that binding. Definitions are created before rules are compiled, so forward references and actions applying other marks work without depending on declaration order. Unknown references, duplicate definitions, invalid source capabilities, and invalid arguments reject the entire candidate.

Authors declare finite instance fields by selecting trusted parameter preset IDs and editing base values. Core presets are ratio, percent, nonnegative amount, and boolean enabled. Hosts may provide additional TypeBox scalar presets, including string enums. Presets own editor/effective schemas and Config operations; uploaded schemas or executable code are rejected. The existing parameter contract validates defaults and edited values. Empty parameter declarations are supported. No independent type checker is introduced.

The pack's unified ParameterCatalog contains both mark fields and rule shared parameters. Install it once in each battle before use. Its existing preflight rejects any address collision before installing any field. The loader itself never mutates a Battle, an existing registry, or previously published definitions. Hosts may publish the returned candidate only when `ok` is true. A failed replacement leaves the previous candidate usable.

Normalized data keeps parameter references, fills defaults, and can be saved and recompiled. Returned mark prototypes, configs, effect/tag arrays, normalized data, and rule result wrappers are frozen. Pack validation is bounded before recursive normalization: depth 40, 65,536 visited values, 1 MiB of text, 64 marks, 128 generated actions and 256 rules; each rule retains its stricter compiler limits.

The host still attaches a compiled skill rule to its skill by ID, installs pack parameters, and registers pack marks/effects in a revisioned SnapshotCatalog alongside other game content. The regression suite snapshots a skill-created mark, recompiles the saved pack into fresh definitions, restores against those definitions, and executes the later mark effect. Restore uses the fresh mark identity and preserves the captured ratio.

Twenty-six tests cover the real skill-to-mark-to-heal flow, normalization and independent recompilation, immutable copied data, empty fields, 17 invalid candidate classes, old-content preservation, atomic parameter installation, trusted string-enum extension, malformed/oversized input, fresh-catalog restoration, cross-mark application, and declared effect ordering. Standards review found no blocking issue. Independent Spec review remains pending reviewer availability; local checks cover #223 E/G and the all-or-nothing candidate rule.

Remaining: skill/species content declarations, multi-pack environment composition and revision hashing, full value presets/captures, templates and copies, editor integration, structured action results, official catalog conversion and behavioral acceptance. This loader does not publish to the production content loader or satisfy those remaining gates.
