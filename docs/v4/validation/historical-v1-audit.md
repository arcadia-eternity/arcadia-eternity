The imported oracle is based on `c086289812885e7a4903b181e2b8989e201452b8`. It is not the final V1 implementation. Searching only that oracle led to incorrect claims that several operations never existed. Candidate coverage is not semantic acceptance; affected candidates require revalidation against the later implementation before admission.

## Field and ordinal audit follow-up

The reproducible report now compares the later and imported type metadata for UseSkillContext, Pet, AddMarkContext, DamageContext and SwitchPetContext. The reviewed historical fields are skill, source, baseMark, stack and switchInPet, not skillId, sourceId, baseMarkId, statLevelMarkLevel or switchInPetId. At the start of this audit, C13 required revalidation: later V1 declares currentHitCount = 1 in context.ts and its SkillPhase loops while currentHitCount <= multihitResult, incrementing currentHitCount. Its metadata includes currentHitCount, while the initially imported metadata did not. Thus the earlier claim that V1 lacked an ordinal field is withdrawn; both pre-use values and multihit mutation behavior required reconciliation. The cursor and loop restoration below now addresses this boundary, with explicit mutation and stage-timing tests.

The historical setIgnoreShield context method, operator, DSL/schema and parser are restored in the working source; see [focused evidence](legacy-ignore-shield.md). ## Temporary-effect lifecycle and action-valued selectors

The pinned revision contains the full temporary-effect storage and cleanup chain, not only the operator:

- `effect.ts` defines `TemporaryEffect(effect, phaseId)`.
- `skill.ts` and `mark.ts` store temporary entries, include their effects in the exposed effect list, and remove entries matching `phaseId`.
- `battle.ts::cleanupPhaseEffects` visits battle marks and every pet's skills and marks.
- Both synchronous and asynchronous `phaseManager.ts` execution paths call that cleanup in `finally`, after popping the config phase.
- The operator binds to the nearest active Skill phase, otherwise Turn, otherwise the current phase; without a phase it returns without adding anything.

These files and line references are now included in the reproducible audit. The current port lacks this chain. Restoration must cover normal completion, failure, nested phases, and snapshot representation before a temporary-effect candidate can be accepted. This is a port omission, not evidence that V1 lacked temporary effects.

For `executeActions`, historical `parseValue` converts operator-shaped values to action functions. However, `createSelectorFromValue` invokes function values (including array members) while resolving the selector. `executeActions` itself later invokes selected function items. This raises a concrete eager-execution concern: a selector intended to choose one action may execute actions before selection. Source existence alone cannot establish the intended choice behavior; characterize the historical parser-to-selector-to-operation path before choosing what to preserve or correct.

## Hit cursor and damage follow-up

The working model and selector metadata now expose the historical currentHitCount initializer of one. Skill execution uses the historical cursor/total loop without resetting the cursor or decrementing multihitResult. The weather candidate now compares against unchanged YAML, and its C07/C10/C13 corrections are withdrawn. See [cursor semantics and evidence](random-weather-application.md).

Inspection of that loop also identifies a separate, unresolved damage boundary: later V1 passes the SkillInstance to DamagePhase and classifies physical/special processing by DamageType; the current port passes the Pet and branches on source instanceof Pet. Restoring the loop alone does not resolve or approve these source/classification/cancellation differences.

## Action-selection characterization

The legacy executeActions operator, action-valued parser path, and selector type are restored. Tests confirm eager execution of flat action arrays before random selection, while nested action groups defer execution until after selection and flattening. All three original definitions parse without rewriting YAML. This resolves the earlier uncertainty about the two paths, but does not approve the flat-choice defect for native migration. See [the action-selection evidence](historical-action-selection.md). addTemporaryEffect remains the missing parser case and requires its full lifecycle restoration.
