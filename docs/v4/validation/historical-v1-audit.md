# Historical V1 baseline audit — 2026-10-20

The imported oracle is based on `c086289812885e7a4903b181e2b8989e201452b8`. It is not the final V1 implementation. Searching only that oracle led to incorrect claims that several operations never existed. Candidate coverage is not semantic acceptance; affected candidates require revalidation against the later implementation before admission.

The comparison revision is `61c349fa7ca35c392b0e751c9238759b02aefcb3`, the parent of the commit deleting the old effectBuilder/parser. It is a recoverable historical reference, not a claim that every historical defect should be preserved or that every file should replace the port wholesale. `scripts/effect-migration/audit-historical-v1.mjs` records source hashes, line references, missing parser/member names and affected current definitions in `historical-v1-audit.json`. It requires the Git objects; its report is checked in for shallow clones. Presence and hash checks establish source existence only, not behavioral equivalence.

## Work completed and remaining

The setRage operation, DSL type, schema and parser have been restored from the pinned historical revision. The operation body is locked by a whitespace-normalized digest usable without Git history. Tests cover both Pet and Player targets, first-value/single-read behavior, duplicates, empty values, clamping, RageChange messages, unchanged parsing of all four current definitions, and parsed execution. This restores an oracle capability; it does not classify those four effects as migrated.

The unpublished direct-assignment native draft and its C16 candidate ledger were removed. No production source YAML was changed. Existing candidate artifacts remain experimental and must not be promoted on the strength of earlier “missing implementation” assertions.

The historical sampleBetween/avg implementations and numeric admission are now restored; see [numeric-selector validation](legacy-numeric-selectors.md). The audit is still open: restore selectorValue spelling compatibility; reconcile rage lifecycle and conditions; reconcile turn predicates/scheduler; review remaining C09–C13 path/reference repairs against historical model fields and schema; inspect other changed historical method bodies, not only missing names. Run relevant full-game and fresh-catalog snapshot comparisons after the reconciled kernel is in place. This report does not approve all other differences merely because no missing name was found.

Validation for this restoration: 17 setRage checks and 118 existing mark-condition/rage-modifier regression checks pass, as do V4 typechecking, lint, declaration build, provenance verification and reproducible audit output. The rage-modifier regression still targets the imported kernel; its passing result does not resolve C15's historical mismatch. Provenance changes are limited to the four restored legacy files.
