## Temporary-effect lifecycle and action-valued selectors

The pinned revision contains the full temporary-effect storage and cleanup chain, not only the operator:

- `effect.ts` defines `TemporaryEffect(effect, phaseId)`.
- `skill.ts` and `mark.ts` store temporary entries, include their effects in the exposed effect list, and remove entries matching `phaseId`.
- `battle.ts::cleanupPhaseEffects` visits battle marks and every pet's skills and marks.
- Both synchronous and asynchronous `phaseManager.ts` execution paths call that cleanup in `finally`, after popping the config phase.
- The operator binds to the nearest active Skill phase, otherwise Turn, otherwise the current phase; without a phase it returns without adding anything.

These files and line references are now included in the reproducible audit. The initial imported port lacked this chain; it has since been restored as recorded below. Normal completion, failure, nested phases, and the settled snapshot boundary have focused coverage. This was a port omission, not evidence that V1 lacked temporary effects.

For `executeActions`, historical `parseValue` converts operator-shaped values to action functions. However, `createSelectorFromValue` invokes function values (including array members) while resolving the selector. `executeActions` itself later invokes selected function items. This raises a concrete eager-execution concern: a selector intended to choose one action may execute actions before selection. Source existence alone cannot establish the intended choice behavior; characterize the historical parser-to-selector-to-operation path before choosing what to preserve or correct.

## Stack-consumption lifecycle restoration

Following the method call beyond its name exposed another imported-kernel omission. Later V1 `mark.ts::consumeStack` delegates to `phases/consumeStack.ts`, while the imported port directly decremented the stack. This lost ConsumeStackContext, OnBeforeConsumeStack, OnConsumeStack and partial-consumption MarkUpdate messages. The context class, operation, phase dispatch, recursive legacy selector, checkSelf owner branch and selector metadata are now restored. Native effect declarations also admit the two restored triggers. No RxJS dependency was introduced.

The pinned historical ordering is preserved: inactive marks return zero; the pre-event may cancel or adjust consumption; the debit is fixed before OnConsumeStack; the message follows the debit; zero stacks use the existing removal phase. Changing actualAmount in the post-event affects the method's returned context value but not the cached debit. Post-event cancellation does not undo consumption. The existing removal phase ignores its available flag; this restoration does not silently introduce cancellation there.

The reproducible audit now includes the historical consumption phase, context metadata and selector member inventory, in addition to parser cases. Empty missing-parser results alone had failed to reveal this omission. Consumption-dependent candidate families require regression verification with the restored lifecycle before production admission.

Restoration validation: 10 dedicated historical checks (including a whitespace-normalized historical operation digest), 239 mark-consumption comparisons and 13 detached-source checks pass against the isolated public bundle. The four additional affected suites (official authored examples, authored snapshots, water-shield content and vital mark sequences) pass 222 checks; native-effect and authoring-boundary suites pass nine more. Authoring-design tests pass 87 checks. V4/design typechecking, V4 lint, declarations, refreshed reviewed provenance and reproducible audit verification pass. Sixteen earlier assertions describing inactive-instance debits were reconciled with the later historical admission guard; no production YAML was edited. Full-game acceptance of all affected effects remains outstanding.

## Damage lifecycle restoration

Effect damage retains OnDamage and the damage message but bypasses those skill-damage hooks. These focused checks do not establish full-game equivalence for every affected candidate.
