# Parameterized water-shield action candidate

`createOfficialWaterShieldCandidate(mark)` provides a native candidate for `effect_skill_add_mark_shuiwenpingzhang`. The trusted caller must supply the declared `mark_shuiwenpingzhang` BaseMark. The factory never fabricates a missing mark, loads the legacy repository, or registers itself in production. The [source ledger](official-shield-candidate.json) pins both the skill effect and its mark dependency; status remains U.

The action preserves selfUseSkill collection, then resolves source owner, maximum HP and source-scoped multiplier at execution. The original selector chain performs `floor(maxHp / 4)` followed by `floor(quarter * multiplier)`. These floors cannot be combined: 407 HP and a 1.5 multiplier produce 151, not 152. The result enters the real AddMarkContext before OnBeforeAddMark, so cancellation, redirection, hook stack changes and existing stack policy still apply.

The public multiplier has base 1 and finite Number schemas, with delta/override operations. Its canonical address is `ae:param:["effect_skill_add_mark_shuiwenpingzhang","shield-stack","multiplier"]`, and its catalog alias is `effect_skill_add_mark_shuiwenpingzhang.multiply_value`. As with the rage candidate, callers must install the ParameterCatalog; aliases do not redirect arbitrary raw ConfigSystem writes. Negative/zero/fractional values remain accepted by this E candidate and pass into the existing mark lifecycle.

Thirty-five tests cover 16 differential scenarios for both skill and mark sources, explicit missing dependency rejection, source/dependency hashes, and the unresolved downstream oracle. Scenarios include current/late HP, scoped/late multipliers, owner change, wrong skill/pet, cancellation, target redirection, hook stack replacement, and higher/lower existing stacks. They compare requested stacks, creation hook input, resulting marks/config/tags and next RNG state, with concrete normal/fractional assertions.

The differential fixture intentionally tests the **application boundary**. It uses the official mark config/tags and an observable creation hook. It does not substitute a no-op in the production catalog or count downstream behavior as converted. The actual chain is shield → OnMarkDestroy → mark_shanghaizengjia → effect_mark_amplify_next_damage_skill_power_with_stack. The last current YAML definition is rejected by the old parser for `useSkillContext`; a dedicated test reproduces that rejection without modifying source data. A [native dependency-closure candidate](water-shield-content.md) now exercises the full chain against an explicit lower-level legacy recipe. Resolving the rejected source spelling and completing acceptance remain required.

Independent Standards review found no blocking issue. Independent Spec review remains pending reviewer availability. This action-only slice does not verify full shield consumption/destruction or snapshots. The separate graph suite now covers those paths; full-game acceptance and production environment integration remain pending.
