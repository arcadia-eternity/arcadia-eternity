# Random replacement of the current skill

`createRandomSkillSelection()` owns `effect_mark_random_use_skill` and `effect_mark_random_use_skill_except_jingshenshikong`. Both compare against unchanged source YAML and retain BeforeUseSkillCheck, priority 0 and legacy checkSelf through the shared sourceOwnsEvent predicate. The second definition excludes base ID `skill_jingshenshikong` before randomness.

The legacy engine already provides UseSkillContext.setSkill and the randomPick implementation. The native adapters reuse that context method and the existing battle shuffle. `targets.selfAvailableSkills` queries the direct skill actor, falling back to the source owner outside a direct skill context, then filters skills by `skill.rage <= pet.currentRage`. Affordability is the historical criterion; no new disabled/ownership/category filtering is invented. The available pool is read at action time. Full shuffle followed by first preserves RNG consumption, including empty and singleton pools.

`ops.setSkill` samples its input once for the selected context list, including an empty list. Missing input skips. With updateConfig true, the existing context method updates power, rage, category, element, accuracy, sure-hit/crit flags, ignore-stage strategy, selected/actual target, multihit and ignoreShield. It does not recalculate priority or other fields beyond that method. With false, only the skill reference changes. All contexts and the chosen skill must belong to the current battle before mutation.

The 144 differential cases cover both definitions, mark/skill sources, twelve variants and three seeds: normal, empty, singleton, exact cost, wrong owner, nested parent, cancellation, late rage, late pool replacement, repeat invocation, suppression and real SkillPhase execution. Assertions compare the selected base ID, updated fields, preserved priority, ordered effect/skill messages, final rage and RNG continuation. Eight operation-level comparisons verify one input read, both updateConfig modes, duplicate/empty contexts and missing input. Compile-only type assertions reject Pet inputs and SkillInstance mutation targets.

Candidate ownership is not production admission. Source YAML is unchanged; full dependency and fresh-catalog snapshot acceptance remain separate.
