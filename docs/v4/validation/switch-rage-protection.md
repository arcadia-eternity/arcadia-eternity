The source's `BeforeRageLoss` trigger and ordered actions are retained. `conditions.ownerLosesSwitchRage` checks the direct rage event, `reduce` operation, `switch` reason, actual SwitchPetContext parent, outgoing pet and target player. An incoming/opponent mark or a switch-labelled event without switch ancestry cannot protect the player.

SwitchPetPhase still runs switch-out/mark cleanup, activates the incoming pet and runs entry effects before charging rage. The existing effect collector includes all teams, so the retained outgoing mark is available without moving the charge earlier or adding a special effect dispatch. The charge now uses the existing RagePhase: loss modifiers and cancellation run before settlement; successful payment emits the normal switch-reason RageChange message. Cancellation retains the existing RagePhase behavior of emitting no paid-loss message.

The unprotected balance remains exactly `floor(currentRage * 0.8)`. The loss is computed as the difference, not `floor(currentRage * 0.2)`. RageContext gains a default-preserving rounding option: ordinary operations still floor; switch loss uses the exact difference so prior fractional rage assignments also reach the same historical final balance. Zero loss dispatches no rage event and does not consume protection. The original effect YAML remains unchanged; runtime hashes and explicit correction evidence are tracked.

The native action first disables the rage context, then removes the source mark through its existing lifecycle. The destruction hook observes the outgoing owner before detachment. No binding or cached owner is introduced.
