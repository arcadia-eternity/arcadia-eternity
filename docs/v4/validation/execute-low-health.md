# Low-health execution

`createLowHealthExecution()` owns `effect_skill_execute_opponent_hp_under_75_hit_or_miss`, compared against unchanged YAML. It retains OnHit/OnMiss, priority 100, the shared self-use predicate, and a strict HP comparison with configurable threshold 75. The opponent position is queried for the condition and queried again for the action. A BeforeEffect HP increase does not retract admission, and an opponent switch redirects the action to the new occupant without rechecking its HP.

The historical executeKill body exists in the pinned later V1 (`61c349fa7ca35c392b0e751c9238759b02aefcb3`, `packages/effectBuilder/src/operator.ts`) and the imported oracle. The new shared `ops.executeKill` adapter validates Pet ownership before mutations, skips already defeated targets, sets HP to zero and isAlive to false, and emits PetDefeated. It does not apply damage, shields or healing. Authored sources are SkillInstance/MarkInstance, so the historical Pet-source-only killer field and lastKiller update do not apply inside the action. Existing lastKiller is preserved.

The operator comment in legacy code says OnDefeat triggers automatically, but inspection of the full chain identifies SkillPhase's final HP check as the dispatch point. That check emits another PetDefeated message, then dispatches OnDefeat and records the attacking player as lastKiller. This candidate preserves the duplicate message behavior rather than silently changing the kernel. Direct action execution does not perform skill completion.

Tests compare 60 source/trigger/scenario combinations, including mark/skill ownership, HP below/at/above threshold, already dead and zero-HP-but-alive state, cancellation, late HP/position changes, nested contexts, repeat invocation, suppression and real hit/miss SkillPhase execution. Comparisons include HP, alive flags, admission counts, ordered effect/defeat messages, killer attribution and RNG continuation. Three additional tests cover configurable thresholds, duplicate targets/existing killer state, and all-target ownership validation before mutation. No source rewrite is required. Candidate coverage is not production admission or full-game dependency acceptance.

Validation result: all 63 focused tests and 84 related vital-operation, historical-damage, last-stand and authoring-boundary regressions pass against the isolated public bundle (147 total). V4/design type checks, scoped lint, declaration build, provenance and historical audit checks pass.
