# Native water-shield dependency closure

`createOfficialWaterShieldContent()` builds three native effects and two immutable mark definitions: skill application → water shield → destroy hook → damage amplification mark → next non-status skill amplification/removal. It supplies the existing shield multiplier ParameterCatalog. The implementation imports no legacy builder, parser, repository or YAML and does not publish to production.

Mark configs, tags and Effect IDs match the current normalized definitions. The destroy effect creates 100 stacks on the current source owner through AddMarkContext. The amplification condition checks owner and category at collection. At execution it reads the current stack, applies `floor(stack * 0.01) + 1` through UseSkillContext.amplifyPower, then uses RemoveMarkContext. In particular, 99 stacks give multiplier 1, not 1.99; a late category change does not rerun the collected condition. An undestroyable mark retains the old behavior of amplifying again on a later invocation.

The current amplifier YAML cannot be parsed because it names `useSkillContext`. The comparison reference therefore explicitly composes the old EffectBuilder, BaseSelector.usingSkillContext, selector arithmetic, condition evaluator and Operators. This reference demonstrates correspondence with that lower-level recipe; it is **not** current-YAML parser acceptance or an approved semantic-change decision. Source YAML and the parser remain unchanged. All graph records remain U, and the existing rejection test remains in place.

The [graph ledger](water-shield-content.json) pins the normalized source hash for every one of the three effects and two marks. A test verifies exact graph coverage and each hash, so editing a condition, multiplier or action order cannot silently leave the handwritten reference stale.

Fourteen tests cover nine comparative chain scenarios, normalized content identity, two JSON checkpoint stages with fresh native definitions, real DamageContext absorption/exhaustion/overflow followed by next-skill consumption, and source coverage/hashes. The real-damage case verifies no HP loss on the first 20 damage, precisely 10 HP overflow on exhaustion, creation of 100 stacks, doubled power and complete removal. Checkpoints taken while the shield or amplification exists restore to the new catalog's exact mark identity and continue the chain.

Standards review found a missing source pin for the handwritten reference; hashes and coverage checks resolve that finding, and follow-up review confirms it. Independent Spec review remains pending reviewer availability. Full-game traces, accepted treatment of the rejected source spelling, environment digest/cutover, and complete official catalog conversion are still required. The earlier action-only fixture remains useful as a focused oracle test but is no longer the only native graph evidence.
