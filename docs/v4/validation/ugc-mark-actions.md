# UGC mark application

This slice connects the bounded rule compiler to the instance parameter lifecycle in #223 G.

A trusted content loader calls `defineAddMarkAction({ id, mark, target })` for a registered standard BaseMark. Target is the finite capability `ownerPet` or `skillTarget`; the generated action statically requires that capability. The action binds a concrete content definition, never a constructor name or uploaded executable code. Normalized author data includes the mark ID as a literal field, so a different ID fails validation. Loading and registering whole authored mark definitions is still a separate content-pack task.

Arguments are `{ mark, stack, duration, instanceParams }`. Stack and duration are positive integers, defaulting to one stack and the definition's positive duration (three for persistent definitions). The existing mark config still controls persistence, maximum stacks and stacking strategy. Instance fields and their editor constraints come directly from `defineMarkInstanceParams`; the nested object has the definition's defaults. Ordinary marks without an instance contract accept only an empty instance object.

Capability metadata now supports nested public slot groups via `{ fields: ... }`, bounded to depth 8 and 128 slot/group entries per declaration. TypeScript derives the nested metadata shape from TypeBox properties. This is trusted schema structure; author data does not provide field paths to execute. At compile time all named fields are checked, unknown nested arguments are rejected, defaults are materialized, and `{ parameter: id }` references retain their identity. A shared rule parameter can feed a nested instance field and a top-level argument of a later action; the existing intersection of receiving constraints and stable Config address remains shared.

All arguments are read at action start. `ops.addMark` creates the real AddMarkContext and invokes Battle.addMark inside the existing action budget. The context copies values before OnBeforeAddMark. After copying, removing or changing the skill-side Config modifier does not affect the Mark. Equal instance bases stack; different bases preserve existing marks and mutex peers. Parameter conflict remains the native operation's non-throwing result; the compiled ordered rule continues with subsequent actions. The general structured action-result/trace ledger is not implemented here.

Author and runtime ranges differ deliberately. `normalize` validates author input against the editor schema; `capture` validates evaluated instance values against the effective schema. For editor range 0..1 and effective range 0..2, literal author input 1.5 is rejected, while a Config-modified value of 1.5 can be captured into a Mark. Installation and snapshot validation use that same runtime contract. No clamping or implicit live source link is introduced.

`core.selfSkillHitTarget` adds a trigger variant that guarantees both ownerPet and the actual skill target. It matches the source's own hit with a concrete target and resolves the target again for each reached action, including changes made by BeforeEffect. The original owner-only trigger retains its prior guarantees.

The saved [recovery mark example](../examples/ugc-apply-recovery-mark.json) demonstrates shared duration and a nested recovery-ratio reference. The host registers its action as `ugc.recovery.applyToOwner`, installs the mark and rule ParameterCatalogs in each Battle, and attaches the compiled effect to the skill. Snapshot hosts register the same revisioned BaseMark and effects.

Seventeen tests cover action-time reads, source independence through SkillUseEnd, normalized JSON recompilation, equal/different-parameter stacking, mutex preservation, late target redirection, missing capability rejection, unknown/range/reference/content errors, defaults and zero, nested/top-level parameter sharing, optional/missing nested objects, declaration depth/count boundaries, narrower receiving ranges, and restored later execution for captured ratios 0.2 and 1.5. The later mark effect in this fixture is native TS. The separate [mark reader suite](mark-parameter-readers.md) now exercises the saved UGC apply and tick rules together through restoration.

Independent Standards review identified the editor/effective-range mismatch; it was fixed and re-reviewed without remaining blocking findings. Independent Spec review remains pending the existing reviewer availability limit. Local checks follow #223 G. Full test and host results are recorded in the migration ledger.

The [pack compiler](content-pack.md) now loads author-defined marks. Remaining: general value presets, templates, editor integration, structured execution records, and complete official catalog migration/acceptance.

The action-budget regression retains its 4096 successful writes and rejection of the next action, across real nested effect contexts. It now places 64 actions in each compiled effect instead of creating 4097 single-action effect contexts. This removes repeated phase setup from the assertion workload without lowering the policy, mocking the runtime, changing the expected count, or raising the explicit 15-second timeout.
