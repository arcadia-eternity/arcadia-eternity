# 官方效果模板目录与组合型 UGC 方案

状态：23 个机制族、49 个原生模板已接入当前工作分支。官方内容盘点基于 `17b3d3ae03bf97cae2e302e7a044dbd4ae96f4dd`；盘点条目数与可配置模板数分别统计。

玩家可以创建精灵、技能和印记数据，选用现成技能，并在技能、印记上配置和组合官方提供的效果。新增执行逻辑仍由可信 TypeScript 实现。普通作品不包含自定义条件表达式、计算公式、脚本或 Rule Graph。

模板从官方已有机制中提取。多个效果只在印记引用、属性、数值等方面不同，就可以归入同一个模板；是否已经抽成公共函数不影响这个判断。特殊机制保留专用实现，不要求所有官方效果都归入少数通用模板。

## 创作对象如何衔接

| 对象     | 玩家编辑内容                                 | 与其他对象的关系                         |
| -------- | -------------------------------------------- | ---------------------------------------- |
| 精灵     | 基础属性、属性类型、可用技能及特性等         | 引用技能和作为特性的印记                 |
| 技能     | 威力、消耗、命中、多段等基础字段，附带效果   | 挂载技能效果；附加印记模板引用一个印记   |
| 印记     | 展示信息、持续时间、层数上限、叠层策略和效果 | 挂载印记效果；可以引用另一个印记         |
| 效果模板 | 官方给出的参数说明和允许的选项               | 固定执行流程，由可信代码实现             |
| 效果使用 | 选择模板，填写参数，拥有独立使用身份         | 隶属于一个技能或印记，不共享可变运行状态 |

例如，玩家创建「迟缓」印记，设置持续 2 回合、最多 3 层、按规定策略叠加，挂载“每层降低速度 10”的模板；再创建一个技能，挂载“命中后给对手附加印记”，选择「迟缓」、概率 30%、初始 1 层。这里出现了新技能和新印记，但执行逻辑全部来自已有模板。

持续时间结束、层数上限与基本叠层由印记自身配置负责，不需要玩家再添加一个“到期销毁”效果。只有“到期后获得另一种印记”等额外机制才使用生命周期模板。

## 机制来源与范围

下面每一行是机制族，可能包含几个语义不同的模板。例如“命中给自己”“命中给对手”可以共享实现和编辑表单，但适用对象、事件次数和目标关系必须明确。本次实现覆盖全部 23 个机制族，具体开放变体见下方“已实现模板”。源码来源中的其他条件变体不自动视为已开放。

### 保留完整实现的机制

随机技能、随机临时效果、技能复制和变换、时光重生、伤害阈值保护、跨效果命名参数修饰等，先保留为带明确依赖的专用内容。能够迁移到其他技能或印记上的，才作为完整效果条目开放；引用了特定技能、印记或参数地址的实现不能默认任意移植。

## 模板需要公开的合同

每个模板需要说明适用位置、参数类型与单位、引用范围、触发时机与次数、对象关系、重复使用规则、状态依赖和结束条件。可视化表单展示游戏概念，内部参数路径、绑定键和上下文名称由实现维护。

- **内容引用**：字符串参数通过 `reference: "mark" | "skill"` 声明引用，可指向本次目录中的官方或自定义内容。装配前验证存在性与类型；作品依赖的来源包与版本解析仍由 #243/#244 负责。现有模板的接收对象是精灵，不提供场地印记模板。
- **属性与数值**：属性使用支持列表；固定值、百分比、百分点、倍率与能力等级分别标明。概率规定为 0 到 100，层数规定整数及范围；其他数值上下界由模板合同确定。
- **印记配置**：持续时间、层数上限、叠层策略和换出行为属于印记。模板可以显式覆盖某次附加的部分字段，默认使用印记本身配置。
- **执行顺序**：保留官方事件和优先级。界面排列不承诺改变全部执行顺序；同一事件、同一优先级内才沿用列表顺序。多段命中、未命中和重复应用需要分别有说明。
- **组合方式**：多个效果独立响应事件，或通过明确引用的印记状态配合。它们不会自动组成传递中间结果的流水线。“消耗若干层并按消费量伤害”需要完整官方模板，不能依靠两个独立条目的偶然执行顺序。
- **状态与清理**：实例参数、来源印记、层数绑定和临时贡献保持独立。到期、主动移除、抑制、换出及恢复快照分别遵循模板合同；不是所有模板在这些场景下都做相同处理。

### 组合与生命周期合同

- `target: self/opponent` 分别表示持有者和对方当前出战精灵；不随技能的实际目标变成自己。受伤反应的对方也指当前出战精灵，不承诺追踪离场的伤害来源。
- `OnHit` 每次命中执行，多段技能可能执行多次；未命中不执行。概率 0 和 100 不抽随机数，其余概率每次判定抽一次。
- 下一次攻击的三个变体都在技能可用性与怒气检查通过后、命中判定前消费来源印记。未命中仍消费，禁用或怒气不足不消费。
- 属性贡献在创建时读取数值。每层属性贡献捕获每层系数，持续跟随来源层数；不是跟随战斗中后续修改的系数。来源抑制时贡献停用，解除后恢复，移除时清理。
- 三类属性模板显式声明随印记持有者转移：旧持有者贡献清理，新持有者重新初始化；转移合并时只更新目标已有印记，避免叠加两份贡献。转移时重新读取配置，技能范围重新选择新持有者当前技能。普通创建事件不会因此重放。
- 后继印记必须是不同 ID，且后继定义不带互斥组；不支持的关系在装配时拒绝。到期与销毁分别有一个模板；同时挂载时到期过程会触发两个事件，不提供隐式去重。
- 属性模板的固定值与百分比共用 `operation` 选择；百分比数值按 100 为一倍，普通属性贡献不额外取整。每层贡献、比例治疗按说明向下取整。威力倍率 1.5 表示原来的 1.5 倍。命中和暴击修正使用百分点。
- 所有模板的引用和结构选择都在装配时固定，运行参数修改不能偷偷切换对象、字段或引用；数值参数保留范围校验。更改结构选择应重新装配内容。
- 伤害收益读取结算伤害 `damageResult`，可能超过目标剩余生命。伤害修正在物理/特殊伤害计算阶段生效，不覆盖绕过该阶段的效果伤害。
- 普通基础包入口拒绝数据规则和替换官方模板定义；引擎原有规则 API 暂留兼容。需要新机制的作者仍通过可信 TypeScript 安装流程扩展。

### 数据与官方实现复用

技能和印记的正式 Schema 已声明 `behaviors`，保存和重新读取不会丢失使用身份或参数。内容目录统一预校验印记和技能引用，并返回所属内容、使用 ID 和字段位置。模板不会创建另一套印记原型。

治疗、连续治疗和状态转移已抽为 [共享流程](../../packs/base/src/effects/shared-plans.ts)，供既有官方效果和新模板共同调用。其他模板复用现有 Authoring API 的属性、伤害、印记和生命周期操作，并声明固定事件合同；没有将 1,065 个官方效果批量替换为新模板。旧效果的特殊条件、取整和目标关系继续由各自实现负责。

作品级依赖清单、包版本解析、编辑器表单、安装界面和房间环境管理分别属于后续 #243、#244、#223。本次交付覆盖模板目录、运行接线、引用校验、数据往返和这些模板的执行验证。
