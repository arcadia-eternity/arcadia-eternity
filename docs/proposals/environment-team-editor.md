# 环境驱动的队伍编辑器

日期：2026-11-18。状态：交互与契约提案，尚未实现。配合[对战环境总设计](environment-system-design.md)、[机制配置](environment-rule-composition.md)与[参考调研](environment-reference-research.md)。本文细化具体页面组织，不新增另一套环境或存储模型。

## 页面骨架

桌面使用“队伍列表＋当前精灵编辑＋本局摘要”三块区域。环境、队伍和状态固定在顶部；配置随选中精灵切换，摘要随当前编辑即时刷新。

| 位置 | 内容                                               | 主要操作                                                                             |
| ---- | -------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 顶部 | 环境、队伍名、草稿保存状态、参战检查状态           | 个人入口可切换查看环境；房间入口只读显示环境名与锁定版本。两个入口均可导入／导出队伍 |
| 左侧 | 精灵头像、名称、顺序、问题数量                     | 添加、选择、复制、移除、排序                                                         |
| 中央 | 当前精灵身份栏；“配招”“养成”两个页签               | 编辑当前精灵                                                                         |
| 右侧 | 本局六维属性、技能摘要、机制生效状态、队伍问题入口 | 展开计算、定位问题、比较变更                                                         |

窄屏将队伍列表改为横向选择，摘要折叠为当前精灵的结果区，问题入口保持可见。数值编辑不依赖拖拽；选择框、页签、排序和错误定位都支持键盘。错误同时有文本与状态标记。

不按“普通／二代／神魔化”划分整页模式：它们可能同时生效，同一页应能组合编辑。配招与养成是展示分组，切页不提交或丢弃另一组改动。

身份栏保留物种、昵称、等级，性别及其他低频字段折叠在更多选项。身高、体重若影响技能，则显示其生效数值并受相同合法性校验，不当作纯外观字段。

### 各入口读取哪个版本

| 编辑入口       | 预览、候选与校验使用的依据                                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 个人组队、仓库 | 用偏好中的来源和环境 ID 定位。桌面本机取工作区已应用的版本，独立静态网页取随站点发布的已准备版本，服务器来源取该服绑定已加载并公开的版本。仅保存声明或准备好待发布候选时，个人预览继续使用原版。切换来源或该来源启用新版后，保留成员及未提交选择并重验 |
| 作者试战       | 对本次构建和候选环境声明做隔离准备。预览使用准备成功的候选版本。准备失败时保留编辑内容并显示原因，上次成功的结果仍标明原版本                                                                                                                           |
| 从房间进入     | 由房间提供建房时锁定的版本。房间号用于定位房间，版本标识用于核对取回的公开规格或个人约战材料。缺材料时仍可查看草稿，补齐匹配版本后再校验                                                                                                               |

从大厅进入组队时，先读选定服务器绑定公开的版本描述，再按该描述取目录和有效规则。只收到列表条目时可以编辑草稿，参战检查显示为待校验。即使玩家也是环境作者，管理页里尚待应用的改动也只供作者预览。

从房间链接直接打开或刷新时，先向当前服务器确认房间、自己的参战席位和建房时锁定的版本，再加载对应目录和规则。房间号可能复用；恢复本场草稿时还要核对房间实例及席位。旁观者可以查看公开信息，提交操作只向仍可组队的参战者开放。房间已关闭则结束房间提交入口；材料暂缺则保留本场编辑候选，允许按原版本补取。两个情况下都可明确返回个人组队。离房恢复原个人偏好，房间打开期间个人偏好对应的版本若有更新，返回后再按该来源重新预览。

环境声明修订用于管理页的保存检查。编辑器接收已准备版本中的目录、有效规则和玩法标识。异步结果写回前，核对入口、来源、玩法版本、队伍与有序成员的修订，以及请求代次。带名称、描述或图标的结果还须匹配本次取得的目录与资源版本。房间入口另核对服务器、房间实例、席位和建房回执中的固定描述；私人 P2P 的准备确认还须匹配本轮准备。服务器建房成功后，以回执中的锁定版本接管本场预览。若与大厅最后一次检查的版本不同，保留选队，重新显示差异并检查整队，再允许提交或 Ready。房间内提交展开的成员副本，并附自己对该房固定描述的准备确认。本场队伍提交成功后即可继续改队，或由当前席位确认 Ready。服务器托管时，本席核对公开目录与展示兼容性；玩家托管时，本席还要核对执行材料。客人可先确认自己的 Ready，房主也可在发起开局时一并提交自己的准备确认与队伍。玩家托管时，由玩家宿主在开局前复验双方队伍。

普通和二代性格共用养成页的性格栏，候选和倍率来自该入口的已准备版本。物种及技能的属性标签、配招页的属性筛选和图鉴相克表也读取该环境目录。精灵配法只记录选中的性格，属性随物种或技能显示。切换到采用另一张相克表的环境时，用原队重新显示相克关系。

## 基础环境与扩展测试环境

首次个人配队且没有环境偏好时进入基础环境：个体输入范围 0–31，按资格提供遗传技能及二代性格，干净草稿不显示神魔化配置入口。扩展测试环境通过顶部环境选择器显式进入，个体范围改为 0–120，并按资格显示神魔化分支与阶段；配招／养成布局保持一致。

从基础切到测试只改变候选、校验与计算上下文，不自动将个体填为 120，也不自动添加强化。测试队伍切回基础时保留超限个体与强化记录，分别标为越界和禁止；已有强化必须可见并可移除，不能因为基础环境不展示新选入口而隐藏错误。提供预览后另存适配队伍的操作，避免改坏测试队伍。

个人入口顶部显示来源、环境名和本次已准备版本。同名玩法从不同服务器取得，或新版使队伍的检查结果发生变化时，玩家可以据此辨认。测试环境名称带“测试”。房间入口固定显示本房的环境名和版本。个人编辑器切环境不修改服务器绑定、队列或房间规则。

## 切环境后选哪一只

仓库中每只精灵对应一套配法。个人组队顶部显示当前队伍和查看环境；房间入口显示锁定的环境版本。选中成员时，身份栏显示仓库昵称、物种和当前队伍位置，旁边显示“使用队伍（数量）”，可展开队名。昵称相同则补充差异字段，例如关键技能、个体或强化阶段；仍相同时显示持久实例标识的可区分短码。重排与重命名后仍能认出同一只。

以两只迪兰特为例，假设其他字段均符合规则。甲队当前用“强化”，六项 120，已神化；仓库另有“常用”，六项 31，无强化。

| 玩家动作                 | 编辑器反馈                                                                                                                        | 实际写入                                         |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 从测试环境切到基础环境   | 甲队原位置仍显示“强化 · 当前成员”，列出个体超限与神魔化禁用                                                                       | 仅改变检查上下文                                 |
| 打开“更换精灵”           | 当前成员固定展示；候选列出“常用 · 单宠可用”和各只的差异。缺技能标出具体引用，来源环境失联时标为无法核对来源；在所选环境仍独立判断 | 浏览或取消不改变成员                             |
| 预览“常用”               | 在原位置代入候选检查整队，分别显示该成员问题及全队组合冲突。有其他未修好的成员也可继续编辑草稿                                    | 确认更换只修改甲队该位置，两只精灵本身保持原配置 |
| 想让两种环境各保留一支队 | 可先复制甲队，再在新队更换成员。再次切环境仍以当前队实际成员为准                                                                  | 复制队伍只创建队伍，选择已有精灵不会增加仓库数量 |

**编辑与换人是两种操作。** 假设“常用”此时被甲、乙两队使用。换技能期间的编辑候选显示两个提交目标：“复制一只给甲队”会新增一只、替换甲队当前成员，乙队继续用原只；“修改原精灵”会更改甲、乙两队引用的同一只。展示引用队名和数量后再写入，队伍多时可展开完整列表。列表按稳定实例身份计算，不能把同物种的其他精灵算进影响范围。当前环境可立即预览合法性，其他队伍的目标环境不可访问时只确认受影响，合法性显示待检查。

玩家在有未提交修改时切换查看环境，候选保留在原队伍和成员上，并按新环境重验。房间入口只能重新取得同一版本的材料。切换成员前可提交或放弃候选。房间内“用于本场”提交临时副本，另存个人仓库才会增加或修改个人实例。

## 配招页

### 技能槽与候选

上方显示已装备技能槽，按环境实际支持的普通／必杀规格分组。下方为当前槽的技能选择器，提供名称搜索、属性／类别过滤和普通／遗传来源筛选；来源是候选的属性，不生成额外技能槽。

已装备但缺失、不合法或分类变化的技能占位仍保留。用户明确替换或移除后才释放槽位。技能总数、必杀要求及遗传数量均由有效规格给出，页面不写死 4＋1。

每个候选展示名称、属性、类别和必要的学习来源。默认展示满足基本资格的候选；“全部”可查看被限制项及具体原因。当前已选非法项始终可见。跨技能组合冲突在选择后的统一诊断中显示，不能仅凭候选可选就显示全队合法。

当前环境只要求选择技能时，配招页只展示槽位和候选。将来某个技能支持编队参数（例如火／水形态），在选中该招的槽位下展示对应选项和结果差异。切环境后若原形态不可用，保留并定位到该槽的该字段。预览给当前队换形态时沿用普通改招的保存范围，可复制一只给本队；房间使用其固定版本验证提交值。环境作者侧设置及扩展示例见[机制配置设计](environment-rule-composition.md#用三类技能需求检验扩展方式)。

### 遗传技能

候选说明可展开查看“物种自带”“环境追加”或“公共遗传池”。原已装备的某招被移除时，重新检查其他学习来源与遗传名额；若无可用来源，保留在原槽并指出具体调整。

命中本环境遗传适用对象且来源开放时，在技能区显示一个遗传选择控件，直接从该物种在当前环境中的有效池选择；不要求用户填写亲本或获取历史。环境不开放且没有既有选择时省略控件。

遗传选择和已装备技能列表通过共享模型联动：

- 若最终确认占普通槽，玩家要在战斗中使用时才分配普通槽，能否仅学习而暂不装备由规格另定；满槽时要求明确选择替换对象。
- 若最终确认独立槽，由槽位规格提供该槽，普通槽不跟着增加。
- 选择／替换遗传结果使旧遗传技能失去唯一来源时，把旧槽标为不合法，并在同一次操作预览中提供替换；不能静默保留为可参战技能。
- 技能同时有满足条件的普通来源时可继续装备，不错误占用遗传名额。玩家已有的遗传记录仍单独验证，关闭遗传来源时不能靠重新标注技能来源掩盖该记录问题。

上述两个槽位方案只在原作证据确定后选择实际默认；首版界面不把未经证实的独立槽做成既定事实。模拟器内部允许临时不一致的编辑草稿，提交参战前必须一致。

特性、纹章也放在配招页，靠近其影响的技能组合。它们与普通战斗状态分开选择，候选来自物种和环境共同限定。

## 养成页

### 数值与性格放在一起

养成页主表为六行属性，列为种族、个体、学习力、性格修正、强化修正、本局结果。窄屏保留个体、学习力、结果，其他列通过明细展开。数字输入是主要控件，滑块只作辅助；学习力显示剩余额度。

性格选择器置于表上方，候选以“普通”“二代”分组。二代组按本环境的性格集合和二代适用对象展示；官方按物种默认资格，社区可对全部物种开放；当前已选但失去资格的性格继续显示并标错。选择项显示名称及增减属性，倍率来自定义；不让用户分别选两项增加再拼一个不存在的性格。

个体范围与默认值由规格提供。导入或切环境带来的超限数值必须完整呈现，不能让控件的 max 属性把 120 改成 31。适配操作与日常输入分开，批量填值只作用于明确选定的当前精灵和字段。

### 神魔化

在同一养成页提供“无／强化分支”和“阶段”两个联动选择，阶段名称由内容定义提供，可显示神、圣、魔、冥等实际名称。环境限制可用阶段，不能直接用任意百分比输入代替原作方案。

只存一个确定方案引用或等价的分支＋阶段选择，不同时保存一份可能冲突的自由加成数组。分支变化后原阶段不存在时保留待修正状态，不自动选最高阶段。方案变化同步刷新主表，允许展开查看修正值与应用阶段。

suppressed 环境保留已存方案，显示“本局不生效”，不把加成计入结果；默认不在此环境引导新增强化选择。forbidden 环境中既有方案显示违规并提供“移除强化”；不因界面隐藏而保留一个用户无法修正的错误。

## 属性明细与比较

借鉴 Path of Building 的结果汇总与计算分解，但默认只显示六维结果。点击某项展开实际计算链，列出输入、采用的规格、各阶段数值和取整。未核实的公式不能以“原作”名义展示确定结果；未实现则显示未支持。

比较一次配法改动时，两列使用同一玩法版本。左列为操作前的当前配置，右列为候选配置，展示字段差异、六维变化与新增／消除的问题。跨版本比较必须各自标出环境名和玩法版本，不能把规则变化误称为某个性格或方案的收益。

预览是计算结果，不回写草稿最终属性。战斗状态假设（敌方、天气、强化层数）属于未来单独的试算工具，不混进本次基础能力表。

## 预设应用

个人入口选用环境预设后，按该来源取得已准备版本。房间入口只提供单宠预设，用房间锁定的版本检查填入的选择。单宠预设可以提供性格、个体、学习力、技能、特性／纹章与强化方案，并记录适用物种、依赖与机制要求。

流程为“选择预设 → 按当前环境生成候选 → 查看差异与问题 → 应用”。默认预设只提供当前物种的配置，不隐式替换物种。首次创建时可直接从空配置或预设开始，后续编辑预设必须先显示差异。

应用按明确字段范围替换，遗漏字段保持原值，清空使用显式空值，避免把缺字段误解为删除。缺依赖或不支持机制的预设可以查看，但不能作为已验证配置应用；仅受当前玩法限制的候选可明确保存为草稿。每次预设应用作为一个可撤销编辑操作，不逐字段触发一串互相覆盖的自动保存。

修改预设产生普通队伍配置，不保持会随预设更新自动变化的引用。环境改变后重新检查，模板来源不赋予额外合法性。

## 状态与错误修正

保存状态和参战检查状态分开，保存成功不会出现“队伍合法”的暗示。

| 状态                     | 用户可以做什么                                                           | 可否提交参战                                                  |
| ------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 编辑中／未完成           | 保存结构可表达的草稿，继续补齐                                           | 否                                                            |
| 校验中                   | 继续编辑；过期结果忽略                                                   | 否                                                            |
| 选择不合法               | 点击问题定位字段，修正或另存                                             | 否                                                            |
| 材料未解析               | 保留内容 ID，恢复材料或明确移除                                          | 否                                                            |
| 机制未支持               | 查看所需能力。个人组队可切环境，房间内须用支持锁定版本的宿主，或另建房间 | 否                                                            |
| 整队通过，房间准备未完成 | 查看已核对目录中的属性与技能、补取本房所需材料                           | 否。例如服务器发布的 P2P 已取得公开目录，仍缺该版玩家宿主材料 |
| 整队通过，房间准备完成   | 保存、导出或提交本场队伍                                                 | 是。房间核对席位和准备确认，实际对战宿主在开局前复验          |

问题列表按精灵与字段归类，队伍级冲突同时指向涉及的多个成员。点击可切换精灵和页签、滚动并聚焦对应控件。错误包含具体原因与规则来源；不把规则 ID 放进默认微文案，技术来源在详情中展示。

“更换性格”“移除强化”“替换技能”直接进入相关操作；自动修复建议必须先展示差异，不能为满足规则自行删宠、改性格或重新分配学习力。部分字段非法时仍可显示不依赖它们的资料，但不展示伪造的完整能力结果。

## 存储、撤销与入口协同

现有仓库按位置移动精灵。迁移后，个人组队编辑有序的仓库精灵实例 ID 列表，作者编辑器编辑项目内完整队伍。两种入口都向页面提供可编辑的候选值。操作与备份规则见[仓库与组队适配](environment-storage-adaptation.md)。

个人草稿按个人档案和队伍 ID 保存；房间草稿按服务器会话、房间实例、参战席位及锁定版本隔离。两间房即使用同一队伍和同一玩法版本，也各自保留本场修改。作者草稿沿用项目和队伍文件身份。个人页切换环境只改变解释上下文。编辑单一使用者的精灵可按原入口策略自动保存；共享成员先保留本次候选，选择影响范围后才写入仓库；预设、批量适配、导入和换物种造成的关联变化先形成一个候选操作。短暂的空数字留在表单状态，不写成 0。

单次操作支持撤销到操作前的草稿；房间已接收的队伍不会因本地撤销自动改变。保存策略仍由现有 delegate 提供，作者入口保留其显式保存流程。写入带草稿修订检查，遇到另一窗口修改不覆盖，保留本地候选并提示冲突。

从房间进入沿用房间固定版本，可从个人队伍生成本场候选。“用于本场”只更新自己的本场队伍副本。返回个人仓库时可明确另存；若选择修改已有精灵，仍须展示受影响的队伍并核对实例修订。离房恢复先前的个人查看环境。本场提交成功时替换自己的副本，并清除自己的 Ready。提交前重新核对席位、房间状态和锁定版本。直接返回、取材失败或提交遭拒时，已接收的队伍保持原值；仍在原房可继续处理候选。

复制队伍后，两队起初引用同一批精灵。在队内修改共享成员时，默认复制一只给本队。选择修改原只或从仓库修改时，列出仍引用它的队伍。保存、撤销和应用预设都通过同一写入入口，避免表单双向绑定直接修改共享对象。

## 开发拆分与扩展约束

在现有 TeamEditor 上按职责拆分：上下文与队伍外壳、精灵列表、配招、养成、结果摘要、问题定位、预设差异。所有控件写入同一个草稿，合法性和计算委托给统一设计中的共享模块。

新增静态性格或强化阶段只改变候选数据，不新增一页。新增机制声明所属展示区域、受支持的控件类型、资格和数据字段；复杂机制可增加专用区域，但不得接管整个编辑器或从包中执行任意前端代码。默认先支持本轮四类机制，不建设通用表单设计器。

## 交互验收

- 默认基础环境维持 31，干净草稿无神魔化入口；测试环境显式选择后开放 120 与已支持的强化方案。
- 基础 → 测试不填满个体或添加强化；测试 → 基础保留并定位两类违规，另存适配副本不修改原队伍。

- 支持遗传的物种可独立选择二代性格和遗传技能；在当前环境无对应资格者看不到新选项，但旧非法值可修正。
- 120 → 31 → 120 往返不改原值；窗口刷新后草稿仍完整。
- 满槽时选遗传技能不自动删除旧技能或增加槽位。
- 神／魔分支切换展示实际阶段与属性差异；不生效环境保留选择、结果不含加成。
- 预设仅修改列出的字段，一次撤销恢复全部修改；依赖缺失不显示成功应用为合法队伍。
- 点击队伍组合错误能定位多个精灵，定位跨页签可用且键盘焦点正确。
- 保存非法草稿成功与参战被拒绝同时准确呈现。
- 编辑器、仓库摘要与引擎计算一致，旧预览不会在异步返回后覆盖新值。
- 用同名的两个玩法版本验收。个人页刷新到新版后，从仍在等待的旧房打开同一队，显示旧版倍率并按旧版提交。迟到的个人预览不能覆盖房间结果。旧房重连仍用旧版，提交前的本地编辑只影响当前候选。
- 在同一来源发布只更新技能描述或图标的版本后，确认玩法标识相同才可复用纯数值结果。旧房仍显示旧资源，新版入口显示新资源，旧房准备回执不能用于新房。
- 在服务器发布的 P2P 房间中，仅加载匹配的公开目录时可检查整队。甲取齐并核对锁定版本的玩家宿主材料后可单独 Ready；乙仅有目录时仍可编辑，整房继续等待乙准备。
- 直接打开私人房间编辑链接，提供同名但不同规则的材料，仍可查看成员，无法 Ready。补齐原版本后可继续编辑和提交。离房后才按个人偏好预览，仓库实例数量保持原值。
- 从甲房返回后，用相同个人队伍进入同版本的乙房。乙房看不到甲房未提交的改招；甲房迟到的加载结果和提交回执也不能改变乙房或仓库。
- 手机端无需横向滚动整张属性表，也能完成数值编辑、查看修正与处理错误。

本次仅形成设计规格，未实现界面或执行交互验收。
