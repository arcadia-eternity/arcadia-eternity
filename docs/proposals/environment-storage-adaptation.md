# 环境切换下的仓库与组队适配

日期：2026-11-18。状态：设计提案，尚未实现。配合[对战环境总设计](environment-system-design.md)与[编辑器规格](environment-team-editor.md)。基础环境为 31 个体＋遗传相关功能；扩展测试环境增加 120 资质和神魔化。

本文中的基础／测试只用作官方样例。仓库与组队适配面向任意可访问且符合契约的环境：不按官方身份分库存、不写死两个选项，所有范围和诊断来自当前解析规格。自定义环境不可用时保留引用与草稿，不静默回退基础环境。

## 当前实现与需要改变的地方

## 个人仓库与队伍成员

当前实现按位置移动精灵。新版个人仓库保存精灵实例，队伍按稳定实例 ID 引用具体的精灵。每只精灵的配法包括物种、个体、性格、技能、学习力、遗传结果和强化选择。仓库可以保存同物种的多份配法。物种 ID 继续指向内容包定义。

| 方案                                       | 两队共用同一配法后，甲队换一个技能                                               | 代价                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 现有移动＋复制                             | 需要先复制才能同时入两队，各改各的                                               | 迁移最小，共同维护十支队时要改十次                                 |
| 仓库保存精灵实例，队伍按 ID 引用（已确定） | 从甲队编辑共享精灵时默认复制一只给甲队。从仓库编辑原配法时更新所有仍引用它的队伍 | 需要引用完整性检查和明确的编辑范围                                 |
| 仓库保存精灵身份，每队覆盖部分养成／技能   | 甲队保存技能覆盖，其他字段继续跟随仓库                                           | 需要逐字段定义覆盖、清除与继承，遗传选择和装备技能跨层校验也更复杂 |

**每只仓库精灵保存一套完整配法。** 同物种的两套配法在仓库里是两只精灵，各有独立身份、昵称、技能和养成值。修改这只可以覆盖原配法；要同时保留两套，就复制出另一只。下文的“配法”指这只精灵保存的字段。

## 队伍引用的操作契约

个人档案保存精灵实例（稳定 ID、修订、物种与全部选择）和队伍（稳定 ID、修订、名称、环境偏好、有序实例 ID）。一只实例可以供多队引用，仓库总数按实例计。单队同一实例至多出现一次；同物种的两只独立实例能否同时参战由环境判断。

| 玩家操作                     | 保存后的效果                                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 加入、替换、排序、移出、删队 | 只改所选队伍的成员关系。移出最后一队的精灵仍在仓库                                                                                       |
| 复制队伍                     | 新队伍有独立名称、顺序和偏好，起初引用同一批仓库精灵                                                                                     |
| 在个人队伍编辑共享成员       | 先形成编辑候选。默认操作“复制一只给本队”列出目标队名，提交时创建新实例并替换该位置。“修改原精灵”列出所有使用队伍，明确选择后才更新原实例 |
| 编辑仅当前队使用的成员       | 常规保存直接修改该仓库精灵。要保留旧配法时显式复制一只                                                                                   |
| 在仓库保存原精灵             | 更新原实例及引用它的本地队伍预览。已提交房间的副本沿用提交时的数据                                                                       |
| 另存适配队伍                 | 确认后创建新队伍，仅为有实际差异的成员创建新实例                                                                                         |
| 删除仓库精灵                 | 有引用时列出使用队伍，先替换或移除引用；未引用时可单独删除                                                                               |

一次保存完成建副本与替换成员。提交时复核预期修订及引用队伍集合；其他窗口新增引用时重新展示变更后的影响范围，由玩家继续。撤销后只清理已无其他引用的本次副本。作者项目队伍文件独立保存完整选择。

## 环境、预览与参战

个人队伍可记住来源和环境 ID 作为下次查看的偏好。仓库摘要及挑选入队使用本次查看的已准备版本。队伍偏好只记录玩家下次想打开的来源；精灵的可选来源提示用于找回曾经的材料。两者都不能作为本次参战的校验结果。从房间挑选成员时统一使用建房锁定的版本，即使个人偏好指向同名对战环境。首次个人使用默认基础环境。查看偏好指向的来源暂时只有声明时，仓库仍可列出全部配法及保存的内容 ID，之前的检查标明当时版本。来源启用新版后，个人预览按新版重新检查。若玩家要复现历史版本，则须找回与当时固定描述匹配的材料。单宠可用表示通过单宠条件，队伍组合限制在整队检查。

按一次一致的档案修订读取队伍及各配法，展开为有序的完整成员选择。缓存键包含档案身份、已准备版本的玩法标识（覆盖内容、规则及计算版本）、队伍身份与修订，以及**有序成员 ID／修订**。即使队伍列表一字未改，仓库保存一次也会使所有相关结果过期。这组缓存键只适用于纯玩法计算。包含名称、技能说明或图标的摘要还须匹配来源及目录、资源版本。房间的材料准备和 Ready 由房间另行确认。反向使用列表可从队伍关系重建。

房间在建房时锁定已准备版本。玩家提交时才捕获队伍副本。仓库的预览缓存可复用相同玩法下的计算结果；房间另外核对参战席位和针对本房固定描述的准备确认，实际对战宿主按锁定版本复核成员。匹配按目标版本重验，CLI 试战使用本次准备的版本。单队导出只需展开成员，原版本失联时也可导出。仓库 ID 和仓库是否在线都不是对局依赖。提交成功后的本地修改只影响下次提交。切换入场环境重新检查，旧队伍超限可保存，受支持的环境容量约束由同一规则计算。导入超额队伍保留成员供修正。

### 同一精灵在多环境中的管理

同一只精灵可以跨环境使用。切换查看环境会重新检查当前实例，保持原成员顺序和仓库数量。需要两套时在仓库保存两只，例如同物种的“常用”和“强化”；队伍成员位记录其中一只的实例 ID。候选按物种筛选，允许玩家挑选其他物种。同名实例的区分、合法性与改动影响见[组队编辑流程](environment-team-editor.md#切环境后选哪一只)。

### 临时 P2P 环境结束之后

例如对手提供的临时包增加了一个技能，玩家据此配队。建房时锁定个人已准备版本的固定描述。重连或换房主后，先核对本地持有的材料；材料缺失时，可用分享文件或 HTTPS 来源补取。取回同名新版时保留本场候选，等待与固定描述匹配的原版。离房后恢复个人查看偏好并释放本次临时引用。仅浏览或临时提交他人队伍不会自动导入仓库。玩家保存的配法则保留物种、技能、性格、数值和扩展选择，并可附来源名称与原私人约战固定描述的版本标识，供以后辨认那份材料。单队分享或备份可携带这两项提示。文件路径、带访问权限的链接及席位凭据留在原会话。其他环境可独立检查这只精灵，找回历史版本只在复现原玩法时需要。即使两间房使用同一份材料，临时改招也只属于原房和自己的席位；在另一房重新从个人队伍生成候选。只有玩家在个人入口明确选择某个环境时，才更新队伍的查看偏好。离房清理仅释放本客户端的临时材料引用；其他仍持有材料的会话或恢复点按各自的生命周期释放。私人约战的信令端仅保存房间的固定引用，无法代为补发个人包。

| 回到仓库后的情况                           | 展示与操作                                                                                                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 分享链接已失效，但仍持有经核对的完整原版   | 用原版重新计算。重新入房时，按仍存活房间的固定描述和当前席位重新确认准备                                                                                     |
| 本地已释放原版，且无法重新取得匹配材料     | 显示“原环境不可用”。可以查看已存字段、复制、导出、替换缺失项或重新提供材料；原环境的最终属性与准入结果显示无法验证                                           |
| 另一可用环境具备全部资料，但规则禁止该选择 | 给出该环境下具体的禁令或越界字段。原配法保留，可另存适配版本                                                                                                 |
| 另一环境没有该技能或物种                   | 指明缺失引用，显示保存的名称或 ID。该项无法解析，不能在该环境参战；明确替换后再查整队                                                                        |
| 后来再次取得材料                           | 按保存的来源提示定位版本，核对取回的材料后重新检查原草稿；同名但版本不同的环境作为新目标独立检查。材料无法找回时，队伍文件依然可保存，原对局数值无法据此复现 |

历史兼容性按实际检查过的版本显示，可按需重新计算。恢复备份时，先恢复成员选择和队伍引用。即使文件带有当时的玩法标识，换设备后也要按所选来源取得版本再检查；进入房间则以房间实际锁定的版本为准。备份中的来源提示无法恢复参战席位或 Ready。准备临时包与永久安装走各自现有入口；来源提示不触发下载或执行。

## 迁移与恢复

- 从旧库与各队内嵌成员的每一次出现各建一条配法，保存原顺序、选中队伍及原字段。即使旧 ID 或内容相同也分别保留，冲突分配新 ID。这样旧副本升级后仍独立，只有玩家后续选择同一配法才开始共享。旧匹配索引映射为稳定队伍 ID，规则集提示只在有明确映射时转换成环境偏好。
- 单队分享（旧 YAML 数组、旧 JSON 及新版）携带完整选择。导入创建本地新记录。全库合并导入按来源 ID 一次分配新 ID，重写选中队伍所需的所有引用，保留文件内部共享关系。完整档案恢复保留文件的身份与引用图。
- 存在悬空成员 ID、格式损坏或不支持版本时保留原文件、报告队伍和位置，整次写入失败。缺内容包和环境超限属于可保存的草稿问题。旧版本原始档案保留到迁移验证完成，新版本重复读取不会再分配 ID。
- 使用档案层已有修订检查与写入结果，网页、桌面和 CLI 共同执行迁移。保存失败后界面保留候选并显示未保存。退回旧程序时使用迁移前备份，新版数据另存保留。
