# 原作养成细节与复杂配队工具参考

调研日期：2026-11-17；补证：2026-11-18。用于补充[统一设计](environment-rule-composition.md)。本次查阅项目源码、开发者文档并静态提取本地原客户端；未运行原游戏或对各参考工具做交互验收。原客户端证据限定于该备份版本。

## 结论

最有用的参考组合是：Showdown 的规则与技能兼容校验、PKHeX 的资格与诊断模型、Path of Building 的分层计算明细、Temtem 的直接配队和预设入口。《激战 2》的模板拆分提供配置复用的补充参考。

不需要完整复制任何一个产品。原作的养成选择应能直接配置，遗传资格、技能组合和运行机制仍严格校验；养成时间、消耗和获取历史不默认进入模拟器。

这纠正了网页表中把“孤傲”和“古怪”写成相同组合的问题。第 34 项只有五项，后面另有一个游离的 `1`。11 月 18 日检查原始 ABC 指令，末尾明确是 `newarray 5`、`pushbyte 1`、`newarray 36`，确认异常存在于这份客户端字节码中，并非反编译器把第六项排错位置。不能将该数组不加检查地导入为六维生产数据。第 25–33 项第六项均为 1；可爱的体力项和服务器计算语义仍需核实。

证据证明此客户端的配置值，不单凭显示数组证明服务端属性公式和取整。官方环境的默认规则为仅支持遗传系统的物种开放二代性格。社区环境可另行指定适用对象。

表包含神化 1–4 星、圣化 1–4 星、魔化 1–4 星、冥化 1–4 星，共 16 个阶段定义。能力面板 `versionOnePetBagPanel.petAbilityPanel.BasePetAblilityPanel.updateDisplay()` 按当前 `evolveLevel` 只取一行，以“+数值”显示为神／圣／魔／冥加成，未累加先前阶段。因此客户端展示支持“当前阶段总加成”的解释。最终属性另从服务器读取；这仍未证明服务端应用位置、性格是否作用于加成及取整顺序。

该版本同阶段神、魔分支的速度字段相同，区别主要在双攻与双防分配。因此不能把[2013 年概括公告](https://game.61.com/news/10029.shtml)中的“魔化速度和攻击更强”直接翻译成另一个速度倍率。设计应选择方案与阶段定义，而非一个随意填写的百分比。

另一张 `PetEvolveConfig__xmlClass` 记录材料与精灵条件，SHA256 `689bc5c9982d1c8cb5f92a46ea3613a9e90f62bb6da394b27328a6f98f385f54`。它能证明客户端曾有获取条件表，不自动证明现代玩法资格；本项目不因此加入材料消耗模拟。

### 个体值：六项字段与旧字段并存

`PetInfo.readPetInfo()` 读取旧 `potential`，又分别读取 `potentialAtk/Def/SpAtk/SpDef/Speed/Hp`；`totalPotential` 返回六项之和。各项 0–120 来自用户确认；11 月 18 日补证 `BasePetAblilityPanel.updateDisplay()` 为六项分别显示 `/120`，进度条除以 120。它证实该版本界面的上限表达；不能从旧 `potential` 字段反推出早期六项是否相同。

同类的 `readBaseInfo()` 从服务器读取体力、物攻等最终属性。客户端备份不等于服务器公式源码；后续应优先找显示计算的消费者、旧版差异或可重现实测，而非反复从字段类型猜公式。

## 参考产品比较

### Pokémon Showdown：技能分别合法不等于组合合法

`TeamValidator` 为技能收集可获得来源，再对整套配置求兼容交集；代码包含遗传、活动、进化阶段及版本来源不兼容的处理。来源交集为空时整套技能不合法。[源码](https://github.com/smogon/pokemon-showdown/blob/master/sim/team-validator.ts)

采用：遗传池校验必须和全套技能来源、数量／槽位约束共同求解；诊断说明具体冲突。范围限制：本项目只表达已有真实规则，不预先复制宝可梦多世代迁移模型。

### PKHeX：复杂资格校验的结构参考

`LegalityAnalysis` 显式持有物种资料、来源上下文、遭遇匹配与逐项结果，并将当前技能、重学技能的结果纳入总判定。源码注明同一实体格式在不同游戏可有不同物种资料，不能临时重新从全局取值。[校验入口](https://github.com/kwsch/PKHeX/blob/master/PKHeX.Core/Legality/LegalityAnalysis.cs)

其 HyperTraining 校验还分别判断机制是否存在、是否开放、等级要求与原始个体值状态。[训练校验](https://github.com/kwsch/PKHeX/blob/master/PKHeX.Core/Legality/Verifiers/HyperTrainingVerifier.cs)

采用：固定内容上下文；资格、玩家选择及环境开关分层；每项诊断保留来源。范围限制：PKHeX 是存档编辑器，本项目不加入训练师、捕获地、随机生成历史等与当前玩法无关的字段，也不把所有高级数据铺满编辑器。

### Path of Building：多层属性与可解释计算

官方项目说明包含装备、技能／辅助技能、天赋、增益及敌方条件参与计算，并提供属性汇总和逐项计算明细；支持的修正与未支持修正有不同标记。[项目说明](https://github.com/PathOfBuildingCommunity/PathOfBuilding/blob/dev/README.md)

采用：总属性保持易读，按需展开种族、个体、性格与神魔化的计算依据；未知修正明确标为未支持。比较配法时使用同一已准备的玩法版本和相同预览条件。范围限制：模拟器无需先做伤害优化器、敌人条件配置或穷举推荐；未来加入试算条件时，应独立于真实队伍与环境保存，不能参与权威准入。

### Temtem Showdown：降低配队门槛

Crema 的原始功能介绍允许直接配置 SV、TV、技能和特性，不需要捕获、繁殖或训练。后续编辑流程为每只提供 Customize 与两个手工配置预设。[1.2 功能介绍](https://crema.gg/temtem/throw-down-with-showdown-the-1-2-update-is-here/)、[1.4 编辑流程](https://crema.gg/temtem/patch-1-4/)

采用：资格条件保留，但玩家直接选择合法养成结果；提供可选的单宠配置预设，再进入精细编辑。预设必须标明适用物种、内容／环境条件，应用前显示改变，并按编辑入口取得的已准备版本重新校验。范围限制：不新增必须刷材料或繁殖的玩法；不把推荐当合法性保证。这是历史功能设计参考，不表示独立客户端当前仍可用。

### 激战 2：可复用配置与实际应用分开

官方设计将技能／专精 Build Template 与装备 Equipment Template 分开复用。同一传奇装备可以在多个模板中保存不同属性选择；模板也可以保留尚未解锁的技能。[官方模板设计](https://www.guildwars2.com/en/news/learn-all-about-build-and-equipment-templates/)

采用：保存的配置、当前编辑对象和本局使用结果分离；“可保存”不等于“当前可使用”。范围限制：Arcadia 先保持完整单宠配置，不提前增加多个相互引用的配装模板库，避免切环境后用户还要分别切多个模板。

## 对当前设计的增补

1. **强化分支与阶段是玩家选择**：神魔化方案来自内容包，作者在环境声明中选择允许范围与生效方式。组队控件读取已准备版本中的有效分支与阶段。不能只用一个布尔值。
2. **计算结果带状态**：至少区分计算完成、选择不合法、材料未解析、机制未支持；不混成一个“无效”或默认数字。
3. **来源校验针对整套配置**：可用技能列表是候选，最终还需全套学习来源、槽位和限制校验。
4. **预设是可选便利功能**：个人组队可通过环境预设选择要查看的玩法，取得已准备版本后再计算；单宠预设只填入玩家选择。从房间应用单宠预设，仍按房间锁定的版本校验。首版可先手工配置，预留单宠预设契约。
5. **修复与比较先显示差异**：切换环境不改原队伍；应用预设或修复建议明确展示属性与选项变化，确认后写入。
6. **支持程度与合法性分别展示**：一个配置通过某版本的规则检查后，仍须由支持该版机制的宿主执行。服务器发布的 P2P 可以先从房间的公开目录检查队伍；每位参战者取得并核对本房锁定的玩家宿主材料后，可确认自己的 Ready。房主也可在开局请求中确认自己的准备状态。私人 P2P 的材料则来自双方选择的文件或 HTTPS 来源。房间采用版本的具体约定见[组队编辑器](environment-team-editor.md#各入口读取哪个版本)。

本轮只更新研究与设计文档，未导入原作生产数据或修改运行逻辑。
