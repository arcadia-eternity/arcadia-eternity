# 简化管理权限

状态：已实现，验证记录见提交说明。2026-11-16。

## 产品模型

每个服务器只有一份管理员名单。用户要么是本服管理员，要么不是。

管理员可管理本服全部资源：设置、环境、内容包、绑定、玩家、对局、备份和管理员名单。普通用户使用游戏功能，不访问管理资源。

删除只读、自定义、服务器管理、工作区管理等角色选项，删除逐项权限配置。环境属于服务器管理的一部分，无需另行授权。新增管理功能自动对本服管理员开放。

后台只提供：

- 查看管理员名单。
- 从本服账户中添加管理员。
- 移除管理员。

无玩家账户的服务器可在后台创建具名管理员登录码，继续支持通行密钥，名单显示管理员名称。内部身份关联由后端处理，界面不要求填写主体 UUID。

## 权限判断

管理请求统一检查：登录凭据有效、身份有效、是目标服务器的管理员。查询页面、修改数据、管理环境和执行任务使用同一个检查入口。

管理员名单变更由一个请求、一个数据库事务完成，保留修订检查和审计。撤销管理员后，已有会话及关联凭据立即失去管理能力，尚未提交的长任务重新检查身份。

已有环境被占用、材料无效或宿主不允许执行第三方代码，仍按对应操作约束处理；这些不属于用户角色配置。

## 保留的范围

本服管理员只管理本服。远程管理权不包含本机文件和桌面权限。可信桌面入口直接拥有本机管理能力。

每个独立管理的服务器使用自己的内容工作区。需要共用内容时，通过内容包或环境导入复用，避免不同服主共写一个工作区。现有共享工作区部署在迁移前拆分，不能直接把一个服务器的管理员扩权到另一个服务器。

宿主登录码提供管理员恢复入口。最后一位管理员不能通过普通后台操作移除自己；并发移除在同一事务内检查。

## 登录与自动化

账户、登录码、通行密钥和记住设备是登录方式，不再各自决定角色。完整人工登录统一按当前管理员名单判定。

已有受限凭据不能静默升级为完整管理员凭据。迁移时撤销并要求完整登录重新登记；普通人工会话、旧设备和通行密钥的处理清单必须明确。

自动化凭据保持独立签发、到期和撤销。新凭据绑定本服管理员身份，只能管理该服务器；移除管理员时立即失效。界面不再提供逐项勾选权限。旧受限 token 继续按旧上限校验直至撤销或到期，不自动扩权；重新签发完整管理凭据须明确显示其范围。

## 实现顺序

1. 后端增加以服务器为范围的管理员名单和统一检查入口。
2. 管理接口与任务提交前检查改为查询管理员名单；环境操作不再要求第二份工作区授权。
3. 后台改为管理员列表、添加管理员和移除管理员。删除刚增加的角色预设与逐项授权编辑器，以及重复的前端权限目录。
4. 迁移已有管理员和凭据，移除普通用户授权流程中的 scope/action 配置，更新文档。

## 迁移

先列出已有身份、完整授权、受限授权、工作区归属和凭据。完整管理员映射到本服管理员名单；本次已确认的线上服主保留管理员身份。仅有部分权限的身份不得自动提升为管理员，列入处理清单，由服主选择授予完整管理权或撤销管理访问。

账号、服务器身份和内容数据保持不变。共享工作区先拆分；受限凭据先确定处置。迁移可重复执行并记录结果，失败保留原状态，保留可恢复的旧授权记录。

## 验收

- 本服管理员能直接完成环境编辑、安装、应用和服务器管理。
- 添加管理员后立即可用，移除后所有入口和未提交任务失去权限。
- 普通用户不能访问管理接口；本服管理员不能管理其他服务器或本机资源。
- 后台无需角色选择、权限勾选、工作区授权或手填主体编号。
- 管理员变更失败全部回滚，并发操作不能移除最后一位管理员。
- 旧受限身份与凭据不会在迁移中自动扩大权限。
- SQLite、PostgreSQL 的授权结果与事务行为一致。

## 实现说明

管理员名单以单个版本化文档保存在既有管理存储中；旧授权行仅作为迁移证据保留。后端操作保留 scope/action 参数用于校验旧服务凭据上限，新管理员不依赖逐项授权。宿主可用 `server admin status` 只读查看迁移清单，使用恢复登录码处理部分授权身份。旧受限人工凭据返回重新登录要求；完整旧凭据在本服务器范围内按当前名单验证。
