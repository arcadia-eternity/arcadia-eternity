先确定问题发生在保存、准备、开局还是战斗结算。下面每种情况都有一个能缩小范围的检查。

| 现象                         | 先看哪里                                                      | 如何恢复或复查                                                                      |
| ---------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 助手找不到霜击               | `workspace_describe` 的目录；`content_query` 的语言和搜索范围 | 切回正确资料包，用本地 ID `strike` 再查一次。依赖内容使用 `scope: "dependencies"`。 |
| 表单显示修改，助手读到旧值   | `workspace_context` 中的草稿与 `source_read` 中的磁盘版本     | 在工作台核对差异并保存，再让助手读取当前版本。                                      |
| 保存发生版本冲突             | 完整记录中的 `file`、`version` 与磁盘上的值                   | 重读，保留双方有意做出的修改，再以新版本提交。                                      |
| 新技能能搜到，进场没有按钮   | 物种的 `learnable_skills`、保存的项目队伍 `skills`            | 保存配招，在新开的对局中检查技能栏。                                                |
| 检查时报引用缺失             | `$ref.projectId`、`kind`、`id` 与 `dependencies`              | 对照实际导出 ID，补齐依赖，重新检查。显示名可翻译，引用使用稳定 ID。                |
| 改了技能后，试玩仍然是旧效果 | 当前试玩任务有无 `stale: true`                                | 保存并重新准备试玩，建立新对局。                                                    |
| 助手没有测试或试玩工具       | 会话是否只读，连接配置是否包含 `--execute`                    | 在自己的可编辑项目勾选执行选项，更新客户端配置并重连。                              |
| 队伍被拒绝                   | `team_validate` 返回的诊断、队伍版本、环境修订                | 按诊断调整队伍，在同一环境重新校验。改过规则时先准备新环境。                        |

## 一个实际定位顺序

“我把减速改为三回合，画面还是两回合。”先读 `data/marks/slow.yaml` 的已保存值，再核对试玩任务的源码版本，最后对照命中当下和回合结束后的读数。前三步能分别定位未保存、旧试玩和观察时点差异。若刚施加时仍为两回合，用[场景测试](./scenarios.md)复现，并保留失败断言、任务 ID 和日志。
