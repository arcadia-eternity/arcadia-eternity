**源文件**　`debug/teams/<队伍ID>.yaml`。`id` 是试战工具选择队伍时使用的标识，`name` 是给作者看的名称，`team` 的第一项为首发。

`species` 和 `skills` 选取环境中可解析的对象 ID。生成项目后使用清单对应的命名空间。`evs` 和 `ivs` 都以六项能力为键。调整赛制后，用实际环境校验等级、配置和配招是否合法。

| MCP 工具        | 输入和结果                                                                            |
| --------------- | ------------------------------------------------------------------------------------- |
| `team_list`     | 查询保存到项目的队伍及文件版本。                                                      |
| `team_save`     | 提交完整 `document` 和 `expectedVersion`。新建传 `null`；编辑已有队伍传刚读到的版本。 |
| `team_validate` | 传试玩任务的 `jobId` 和已保存的 `teamId`。读取 `valid` 及诊断。                       |
| `battle_create` | 传试玩 `jobId`、两支已保存队伍的 ID 和固定种子，创建独立对局。                        |

只改队伍时，保存后开新局即可读取新队员。已经开始的对局保留开局时复制的双方配置。规则或资料包改变后，要重新准备试玩。
