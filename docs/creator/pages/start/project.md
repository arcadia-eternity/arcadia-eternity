一次霜击串起了三个可以独立修改的对象：霜团的技能表决定它能学什么，技能 `strike` 在命中时执行行为，印记 `slow` 决定减速能维持多久。先找出负责这一条规则的对象，后续修改和测试就容易定位。

## 从玩法找到源文件

| 想改什么                     | 在模板里打开                                                    | 怎么核对                   |
| ---------------------------- | --------------------------------------------------------------- | -------------------------- |
| 基础速度、可学技能           | `data/species/pet.yaml`                                         | 查看霜团的属性和技能表     |
| 威力、命中率、消耗、行为引用 | `data/skills/strike.yaml`                                       | 在技能编辑页对照名称与 ID  |
| 印记持续时间、层数和刷新策略 | `data/marks/slow.yaml`                                          | 首次命中与再次命中分别观察 |
| 命中后对谁做什么             | `src/effects/slow.effect.ts`                                    | 用场景测试触发命中和未命中 |
| 图片、音效、显示名和说明     | `assets/`、`data/resources/`、`data/presentations/`、`locales/` | 在对应语言和试玩画面检查   |
| 测试队伍与回归条件           | `debug/teams/`、`test/pack.test.mjs`                            | 切换队伍，重跑场景测试     |

## 看懂三种名字

「霜击」是中文语言文件中的显示名。`strike` 是源项目内的技能 ID。团队文件用带命名空间的标识选技能，如模板中的 `example-pack:strike`。创建项目后应使用项目清单里的真实命名空间。

精灵的技能表在源 YAML 里通过 `$ref` 的 `projectId`、`kind` 和 `id` 指定目标。跨包复用技能时，把对方的 npm 包加入自己项目的 `dependencies`，再从已声明的依赖中选择对象。改中文名只需更新语言条目；已分发内容的稳定标识会被其他项目和队伍引用。

## 文件从创作者到玩家的路径

在可编辑项目里保存，会写入源文件。准备试玩，会按当时保存的内容和依赖组装出可运行的版本。生成发行包，会产出供安装的 `.tgz`。玩家把包加入具体环境并应用后，才能在该环境中使用这些内容。想确认自己正在测哪一版，可核对试玩任务的 `sourceRevision` 和 `stale`。[打包与安装](../publish/local.md)
